# Базовый профиль HCP для семейства Astra Linux

Это **авторский профиль HCP** из 18 проверок конфигурации только для чтения.
Он не является профилем производителя Astra Linux, CIS Benchmark, заключением
ФСТЭК или проверкой всех механизмов защиты ОС. CVE оцениваются отдельным аудитом.

Применимость определяется по семейству Astra в `os-release`, без списка
разрешённых выпусков. Каждое правило проверяет наличие необходимых возможностей.
Требуются Python 3.5+, запуск с правами root и OpenSCAP с плагином SCE. На системе
другого семейства правила возвращают `notapplicable`; недоступные наблюдения —
`unknown`. Отсутствие подходящего правила или средства проверки не означает
защищённость системы. Совместимость с каждым выпуском и архитектурой Astra нужно
подтверждать отдельными прогонами на соответствующих машинах.

| Область | Проверки | Границы оценки |
| --- | --- | --- |
| Файлы учётных записей | Владелец, группа и права passwd, group, shadow, gshadow | Обычные файлы, традиционные права Unix; ссылки требуют ручной проверки, ACL отдельно не оцениваются |
| Локальные учётные записи | UID/GID root, единственный UID 0, отсутствие пустых паролей shadow | Только локальные записи; LDAP, NIS, PAM и доменные политики не охвачены |
| SSH | PermitRootLogin, PermitEmptyPasswords, MaxAuthTries, X11Forwarding | Эффективная глобальная конфигурация `sshd -T`; отдельные контексты Match не оцениваются |
| Ядро | ASLR, protected_hardlinks, protected_symlinks, ptrace_scope, kptr_restrict, dmesg_restrict | Текущие значения доступных интерфейсов `/proc/sys`; сохранение после перезагрузки отдельно не оценивается |
| Аудит | Активность auditd.service | Через systemd; полнота audit-правил, доставка и сохранность журналов не оцениваются |

Профиль выбирается в HCP через встроенную политику:

```text
datastream: /__hcp_builtin__/astra-baseline.xml
profile: xccdf_org.hcp_profile_astra_baseline
```

Значение `datastream` выше — идентификатор встроенного контента HCP, а не путь,
который нужно создавать на машине. Плейбук `openscap-audit.yml` копирует XML и
`check.py` во временный каталог целевого хоста, собирает единый datastream через
`oscap ds sds-compose`, вычисляет SHA-256 полученного файла и запускает полный
выбранный профиль. Контрольная сумма охватывает и XCCDF, и встроенный код SCE.
Временные файлы удаляются в блоке `always`. Программа не устанавливает пакеты и
не исправляет настройки во время оценки. Существующий запуск явно заданного
внешнего datastream остаётся доступен.

При явном `hcp_openscap_keep_arf=true` контроллер сохраняет сырой ARF и, для
встроенной политики, точный собранный datastream рядом с отчётом. Эти материалы
позволяют воспроизвести содержание проверки; ARF может содержать сведения о
конфигурации хоста. По умолчанию сохраняется нормализованный отчёт, временный
ARF удаляется. SCE передаёт фактические значения через `check-import stdout`;
парольные хэши и полное содержимое shadow в вывод не включаются.

Проверка `passwd_permissions` включает фактическую смену прав **временного файла**
в отдельном сценарии приёмки, а не изменение `/etc/passwd` рабочей системы.
Workflow `astra-scap.yml` проверяет реальный OpenSCAP на Ubuntu: исходный профиль
должен честно признать Ubuntu неприменимой. Отдельный явно изменённый образец
идентификации позволяет проверить исполнение всех правил, сохранение ARF,
нормализацию, изменение результата при нарушении прав и восстановление. Такой
тест **не объявляется живым аудитом Astra**.
