Одна управляющая Ubuntu, настоящая Astra SE 1.7.6.15 base и дополнительный
Debian/Ubuntu контрольный хост. Три контура: SSH/inventory, OpenSCAP + выбранная
OVAL-база, обратимые изменения поддержанного UFW/firewalld. Новые сканеры,
универсальное исправление пакетов и расширение матрицы ОС отложены.

## Этап А: совместимый кандидат

1. Сохранить main равной GitHub; интегрировать изменения PR #74, #78 и #79
   в локальную RC-ветку без перезаписи исторических доказательств.
2. Закрыть P0-02: сохранить evidenceProjection через валидатор, SQLite и
   штатный запуск. Компактное представление сохраняет все ID и точные
   результаты определений; неизвестный режим отклоняется.
3. Закрыть P0-03: единая объектная platformApplicability в новых отчётах,
   совместимость с прежней строковой bounded-проекцией. Подтверждение требует
   false исходного определения, той же базы, актива и поколения; неизвестность
   и смена области не считаются устранением.
4. Проверить integrity и source drift из #78/#79 вместе с настоящим адаптером.
   Регрессии, типизация, production-сборка и HTTP-проверки на изолированных данных.
5. Добавить отмену устаревших PR CI без отмены main/manual доказательств.
   Сохранить обязательные проверки релизного SHA и явные ручные native workflows.
6. Ввести один текущий паспорт релиза; исторические результаты оставить
   неизменными. Локальные тесты не называть exact-head GitHub CI.

## Этап Б: операторский E2E

После А: мастер подключения с независимым SSH fingerprint и asset binding;
инвентарь; 18 правил до/после контролируемого нарушения/после восстановления;
полная выбранная XML OVAL; исходные JSON/ARF; UI/API/архив/PDF; отдельный
firewall-переход с внешним сетевым эффектом и откатом. Только реальный стенд,
никакой подмены настоящих результатов фикстурами. Изменение целевого сервера
требует конкретного согласованного действия и доступной консоли/snapshot.

Приёмка Б: комплект оригиналов, SHA, timestamps, идентичность актива и
результат независимой проверки восстановления. Исходные четыре failed правила
не объявляются устранёнными только по опыту pass → fail → pass.

## Этап В: эксплуатация и восстановление

Операторская приёмка #43: preflight, сеть/HTTPS и ограничение входа, сессии,
HMAC с независимым anchor, backup и восстановление на отдельной Ubuntu,
новый вход/SSH, зависимости и воспроизводимость поставки. Лабораторные
проверки не заменяют подпись оператора. EOL Ansible для Astra 1.7,
доверенность CVE-источников и нагрузка 1/3/5 хостов остаются явными рисками.
