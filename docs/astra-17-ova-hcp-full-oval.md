# Astra Linux SE 1.7.6.15 — полная выбранная область оригинальной OVAL 1.7

**Статус:** отдельный исследовательский сценарий для **подлинной** native
Astra Linux SE 1.7.6.15, который необходимо подтверждать фактическим
результатом exact-head CI. Его исходные unit-тесты являются лишь проверкой
контракта, не доказательством успешного OVAL-аудита.

## Основа

Официальный исходный OVA-стенд (base, x86_64) прошёл реальный CI
[42027952736](https://github.com/Danil-super/hardening-control-platform/actions/runs/42027952736):
оригинальные байты OVA, настоящая Astra 1.7.6.15, два SSH с закреплённым
ключом. Для следующего этапа существует [PR #72](https://github.com/Danil-super/hardening-control-platform/pull/72)
с реальным штатным HCP Ansible / 18-rule OpenSCAP до, во время
контролируемого нарушения и после восстановления. **Без успеха этого
профиля выполнять OVAL и заявлять полную приёмку нельзя.
Реальная Astra 1.7.6.15 использует Python 3.7; современный Ansible 2.21
встроенного GitHub runner его не поддерживает. Для **временного
лабораторного контроллера** только в CI выделено изолированное
окружение ansible-core 2.17.14 под Python 3.12. Ansible 2.17 находится
в EOL с ноября 2025 года и **не предлагается для production**.
Механизмы защиты и штатный Python Astra не меняются.**

Новый независимый workflow:
`.github/workflows/astra17-ova-hcp-oval.yml`;
модуль: `deployment/tests/verify_astra17_ova_oval.py`.

## Точный фиксированный источник производителя

Astra Linux OVAL для 1.7 x86-64:
https://dl.astralinux.ru/artifactory/al-oval/1.7_x86-64/oval-definitions-alse-1.7.xml

Snapshot, сверенный с официальным Storage API **4 ноября 2026**:
- **134668815 байт**;
- SHA-256 `c9364c80d664907dc472475d2ef57689c314abecede7a58e7e9dae8250891d17`;
- область: установленная Astra Linux 1.7, x86_64.

Текущее содержимое поставщика может измениться. Несовпадение
**любого** байта при скачивании приводит к FAIL и требует самостоятельного
расследования, а не автоматического принятия новых определений.

**Контрольная сумма из того же Artifactory не является независимой цифровой
подписью изготовителя.** Ни одно совпадение пакетов/CVE не свидетельствует
о стопроцентном обнаружении всех существующих уязвимостей.

## Реальный сценарий в изолированной GitHub VM

1. Проверить исходный нативный OVA/SSH, запустить штатные HCP
   `collect-facts`, `package-inventory` и три настоящие исходные
   OpenSCAP ARF/JSON по 18 правилам.
2. Запретить переход к OVAL, если профиль неполон, содержит unknown,
   исходные rule IDs изменились или исходные права не восстановлены.
3. Сохранить в приватном каталоге и проверить точные байты и SHA
   выбранной OVAL 1.7 XML.
4. Потоково извлечь **все** оригинальные идентификаторы `definition`
   из настоящего XML. Дубликат, неправильный формат или отсутствие
   определений — FAIL.
5. Запустить **на том же настоящем госте** неизменённый штатный
   `ansible/playbooks/astra-oval-audit.yml`. База загружается только
   управляющей машиной и передаётся по управляемому SSH.
6. Сверить `id=astra` и `astraVersion=1.7.6` из реального scanner
   report, точный SHA-256 оригинальной базы, факт выполненной оценки,
   успешный код OpenSCAP, отсутствие `partial` и причины отказа.
7. Требовать **полное точное совпадение множеств определений**: число
   `definitionResults`, уникальность ID и полный набор должны совпасть
   с настоящим XML. Недостающие или дублированные элементы нельзя
   заменить выборкой одного CVE.
8. Честно сохранить число `true`, `false`, `unknown` и
   `not applicable`, а также отдельные SHA исходных результатов.
   `error` и `not evaluated` не являются подтверждённой полной оценкой —
   такой результат требует **FAIL** с явной причиной.
   `unknown` не становится `passed`, `false` не является
   удостоверением отсутствия всех CVE.
9. Оригинальные XML, raw guest результаты, SSH и machine-id остаются
   в приватном каталоге временной CI VM, без публичной загрузки.
   В CI artifact попадают только строго ограниченные поля,
   агрегаты и checksum.

При любом неуспешном сканере, отсутствии OpenSCAP, неполном source
или спорной версии из тех же байтов — **FAIL**.

## Границы результата

Даже успешный полный проход **выбранной вендорской XML** ещё не доказывает:
- полноту всех CVE и независимую подлинность источника;
- гарантию безопасности хоста и применимость исправлений/backports
  без независимой сверки с бюллетенями производителя;
- штатную production-публикацию через HCP с
  `assetId/generation` и полноценный PDF;
- реализацию мастера подключения реальных пользователей на Ubuntu;
- независимую сохранность/откат всей Astra или правил PARSEC;
- поддержку уровней `adv/max`.

Для итоговой сдачи потребуются фактические исходные протоколы,
штатная публикация доказательств, авторизованная приёмка
[issue #43](https://github.com/Danil-super/hardening-control-platform/issues/43)
и независимый контроль производителя [#12](https://github.com/Danil-super/hardening-control-platform/issues/12).
Задача [#40](https://github.com/Danil-super/hardening-control-platform/issues/40)
остаётся открытой до выполнения всех её требований.
