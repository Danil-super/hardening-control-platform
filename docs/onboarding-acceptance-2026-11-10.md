# Мастер подключения Astra — практическая проверка 10 ноября 2026

Проверен новый проход мастера в браузере: от пустого списка хостов до аудита
и завершения работ. Использовались отдельный HCP с пустым runtime и настоящая
временная ВМ Astra SE 1.7.6.15 из ранее проверенного холодного снимка.
Копия работала в host-only сети, 2 vCPU / 2 ГиБ; полная OVAL здесь не запускалась.
Рабочая Astra продолжала работать, её inventory и ключи не перенастраивались.

## Найденное исправление

До исправления установка ключа всегда добавляла пустую строку перед ним.
Closeout удалял ключ, но оставлял строку. Доступ и права не повреждались, однако
содержимое authorized_keys отличалось от исходного. На реальной копии это
обнаружила побайтовая проверка; неудачный протокол и runtime сохранены отдельно.

`4bcb500` добавляет разделитель только при отсутствии завершающего перевода
строки. Проверены настоящие shell install → Python revoke на временных файлах:
пустой файл, прежние ключи, комментарии, существующие пустые строки, повторная
установка и строка без завершающего newline. Для последнего случая добавленный
разделитель остаётся после revoke: точный возврат таких байтов потребовал бы
отдельных исходных метаданных. Существующие пустые строки не удаляются.

Проверки сначала воспроизвели дефект. После исправления прошли 368
Python/Ansible-тестов и 125 HTTP-проверок; полный реальный цикл повторён на
свежей копии снимка и пустом runtime. Изначальные ошибки селектора браузера
и контрольного вычисления machine-id исправлены в испытательном скрипте;
обычный SHA файла не подменяет доменный HMAC идентичности HCP.

## Локальная установка

Код: `4bcb500e6b287f72d64ae91bb4d95ee2862b1252`.
Образ: `sha256:84828d4e8ac95b42abe69343153ab7aa042135959a42fe59a9f2d2bee72a329d`.
Это точечное обновление Python поверх предыдущего образа, без изменения
зависимостей/frontend. Байты всех 72 поставляемых файлов Ansible совпали с Git.
Рабочий скрипт совпадает с испытанным на ВМ; последний дополнительный слой
обновляет только тестовый файл. На финальном образе повторены 368 тестов с полным
контекстом исходных fixtures; запуск без deployment fixtures дал отдельную
ошибку отсутствующего тестового файла и успехом не считается.

Перед установкой сохранён SQLite backup. При каждом переключении совпали
13 таблиц данных, 98 отчётных файлов, env, mounts и параметры запуска.
Основная панель healthy на `http://127.0.0.1:3000`; fingerprint/asset binding
рабочей Astra повторно подтверждены, прежний credentialId сохранён.
Страница «Хосты» проверена после установки в desktop/mobile.

Новый GitHub CI и полный повтор всех сканеров на этом SHA не выполнялись:
изменён только монтаж строки SSH-ключа. Отдельная восстановленная Ubuntu,
независимые anchors, нагрузка нескольких хостов и подпись оператора остаются
незакрытыми этапами. Ограничения legacy nftables и Trivy/Astra не сняты.
