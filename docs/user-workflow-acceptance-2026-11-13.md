Ansible этого опыта создаёт отчёт HCP, а не отдельный оригинал внешнего

## Порядок проверки оператором на реальных хостах

1. Начать с одного разрешённого хоста: сверить SSH fingerprint, ОС, пользователя
   и sudo. Для Astra проверить требуемый PARSEC-контекст; доступ к SSH сам по себе
   не подтверждает полномочия чтения всех настроек или изменения firewall.
2. Выполнить сбор сведений, затем нужные проверки по одной. Сопоставить выбранный
   инструмент, время и хост с отчётом; для partial прочитать конкретные ограничения.
   Переход на другую страницу не должен прекращать серверное задание.
3. Скачать PDF HCP и доступный оригинал инструмента. Сверить несколько находок
   с оригиналом, не считать отсутствие оценки риска отсутствием уязвимостей.
4. Добавить одну находку в план и удалить ненужный черновик. Согласованный пункт
   и исходные доказательства проверять отдельно от удаления черновиков.
5. Только после исходного аудита, резервной копии и готовой консоли проверить
   изменение одного согласованного порта вне SSH; затем откат, новое SSH-соединение
   и контрольный аудит. Массовые изменения до этого не выполнять.
6. При успехе повторить проверки на оставшихся разрешённых хостах, всего до трёх;
   три полных OVAL одновременно этим протоколом не подтверждены.

Можно начинать поэтапную приёмку реальных хостов. Публичное размещение пока
не подтверждено: остаются CVE/Ansible EOL, HTTPS и независимое внешнее хранение.
Практический этап OpenSSH отложен оператором; полный перечень границ — в паспорте.
