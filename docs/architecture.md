# Архитектура

Hardening Control Platform состоит из веб-платформы, демонстрационного движка аудита и Ansible control node для централизованной работы с несколькими Linux-хостами в локальной сети.

```text
Веб-платформа
  Главная панель
  Профили аудита
  Демонстрационный аудит
  Просмотр результатов проверок
  Планировщик исправлений
  Имитация резервных копий
  Отчет до/после
  Экспорт JSON и HTML
  Страница хостов и запуск разрешенных Ansible playbook'ов

Главный компьютер / Ansible
  Inventory хостов локальной сети
  Ping и проверка SSH-доступа
  Автообнаружение SSH-доступных хостов
  Безагентный сбор фактов и аудит
  Сбор событий из auth/syslog/UFW/Suricata
  Планировщик audit-playbook'ов
  Журнал инцидентов
  Запуск response-playbook'ов после подтверждения
  Сохранение JSON-отчетов в ansible/reports
```

Веб-часть хранит демонстрационные данные в TypeScript-модулях. В демо-режиме выбранные действия создают записи резервных копий в памяти браузера, отмечают связанные проблемы как исправленные, запускают повторный аудит и формируют отчет “до/после”.

Для нескольких устройств в локальной сети используется каталог `ansible`. Главный компьютер выступает Ansible control node: подключается к хостам по SSH, запускает playbook'и из allowlist и сохраняет результаты аудита локально. Постоянные агенты на управляемые хосты не устанавливаются. Веб-страница `/hosts` обращается к локальным API route'ам Next.js, поэтому этот режим предназначен для локального запуска сайта внутри сети, а не для Vercel.

Общие сущности проекта: `AuditProfile`, `Finding`, `Remediation`, `AuditReport`, `BackupRecord` и `BeforeAfterReport`.
