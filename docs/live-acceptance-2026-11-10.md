Локальный стенд: HCP на управляющей Ubuntu и ранее подключённая Astra Linux
SE 1.7.6.15, 4 ГиБ памяти, Python 3.7.3. Проверялась настоящая ВМ через
сохранённые SSH-ключи и привязку актива; синтетические отчёты не использовались.
Код исправлений: `4e29be2`, `b277383`. GitHub CI этих коммитов не запускался.

## Изменение firewall и откат

До изменения создан живой снимок VMware. Клиент ожидания получил тайм-аут,
но завершение сохранения памяти/снимка подтверждено журналом гипервизора.
Восстановление самой ВМ из этого снимка не выполнялось.

Временная служба слушала выделенный TCP-порт, разрешённый только управляющей
машине. Она имела автоматический предел жизни 900 секунд. Изменения HCP
применялись только к этому тестовому порту; настройки SSH и рабочих служб
не менялись. Внешний замер сделан с управляющей машины, а не через localhost ВМ.

1. До изменения TCP-соединение получало уникальный ответ тестовой службы.
2. Предпросмотр HCP не изменил конфигурацию и фильтры.
3. После применения соединение блокировалось; сама служба оставалась запущена.
   Новое SSH-подключение с закреплённым ключом работало.
4. Откат HCP восстановил доступность и тот же уникальный ответ.
5. Совпали байты файлов UFW, владельцы, режимы и расширенные атрибуты/метки,
   политики IPv4/IPv6 и порядок правил внутри каждой цепочки.
6. После удаления временной службы и её разрешающего правила исходные файлы,
   фильтры и статус UFW совпали. Повторный OpenSCAP снова дал 14/4.

Первый контроль ошибочно требовал неизменного глобального порядка независимых
цепочек в `iptables-save`: Docker переставил блоки, сохранив правила каждой
цепочки. Исходные данные попытки сохранены. Контроль уточнён и самопроверкой
отличает перестановку блоков от изменения политики или порядка правил внутри
цепочки. Второй полный цикл прошёл. Это проверка конкретного обратимого
изменения firewall, а не полного отката ОС и не всех сетевых путей.

## Сценарии и восстановленный контроллер

Ранее сохранённый runtime действительно извлечён в новый отдельный volume:
107 файлов побайтно совпали, SQLite исправен, проверена HMAC-цепочка из 234
событий. Её head/count сверены с сохранённым префиксом текущего исходного
контроллера; это не независимый внешний anchor. Два скопированных сеанса
отозваны только в остановленной копии.

Основная панель остановлена до сетевого запуска восстановленной копии.
Копия слушала только loopback на отдельном порту. Из неё выполнены новый
SSH с проверкой ключа/актива и полный браузерный цикл собственного сценария:
создать из шаблона проверки пакета → изменить комментарий → сохранить →
настоящий Ansible syntax-check → проверить python3 на Astra → удалить черновик.
Найден установленный Python 3.7, changed=0, unreachable=0, failed=0.

Выполнение собственного YAML разрешалось только на этой тестовой копии.
Production lock основной панели не отключался. Тестовый контроллер удалён;
основная панель снова healthy после паузы 20,77 с, её 13 таблиц, отчётные
файлы и конфигурация не изменились. Это восстановление контейнерного runtime
на том же компьютере; новый перенос на отдельную Ubuntu этим не подтверждён.

## Исправления, обнаруженные на настоящей ВМ

1. Неактивный firewalld возвращал код 252 и `not running` в stderr. Старый
   сборщик считал состояние неизвестным и блокировал готовность UFW.
   Теперь учитываются оба потока при точном коде/сообщении; ошибки доступа
   по-прежнему unknown, непрозрачный packet-аудит по-прежнему manual.
   Код 252 соответствует [официальному NOT_RUNNING](https://firewalld.org/documentation/man-pages/firewall-cmd.html).
2. Legacy Ansible преобразовывал подготовленное JSON-доказательство проверки
   OVAL-базы в текст Python-словаря. Первый запуск сохранил честный partial
   с ошибкой JSON; исходный неудачный отчёт оставлен в истории. Исправлена
   сериализация на границе argv. Повтор на Astra завершился без partial.

Регрессионные проверки: 618 web, 122 HTTP и 363 Python/Ansible; профильный
тест запускает настоящий legacy и modern Ansible, проверяет подготовленный,
загружаемый и локальный варианты, а также буквальное сохранение шаблонного
текста без выполнения lookup. Все эти проверки повторены на полном итоговом
образе; production build и pip check трёх tool-окружений прошли.
Приватные XML/PDF, логи, снимки и ключи в Git не включаются.
