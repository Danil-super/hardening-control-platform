# Память при сверке исходника PDF

Следующий локальный срез общего бюджета RAM: в `renderAuditReportPdf`
убраны две полные сериализации JSON, которые служили только сравнению
прочитанных данных. Используется стандартный `util.isDeepStrictEqual`.
API, лимит исходника 64 МиБ, защищённое чтение файла, evidence lock,
SHA-256 точных исходных байтов и проекция содержимого PDF сохранены.
Новых зависимостей, настроек или изменений БД нет.

Сравнение проверяет вложенные значения, типы и порядок элементов массива;
порядок ключей объекта значения не имеет. Неравные данные по-прежнему дают
`report_changed` до запуска renderer. Проверены null/boolean/number/string,
собственное поле `__proto__`, точный digest и граница блокировки.

## Измерение

База — код `28a14e7`, образ `e0a95d2b`, CPU=1,
memory=memory+swap=2 ГиБ, без сети. В каждом замере свежий Node-процесс;
настоящие чтение/нормализация отчёта и защищённое чтение оригинала,
заменён только renderer, чтобы измерять подготовку снимка отдельно.
Синтетический JSON: 33 554 557 байт, включая русский текст;
SHA-256 `59c872dbd82eb6a074dbb8d18ea5801873200e2a2f8f8cb81c1735aa97f0eadb`.
Digest независимо вычислен Python и совпал во всех четырёх измерениях.

| Код | Пик RSS процесса, два замера | Подготовка снимка |
| --- | --- | --- |
| Прежний | 521 248 768 / 522 428 416 байт | 345,6 / 354,8 мс |
| Без сериализаций для сравнения | 353 144 832 / 357 175 296 байт | 192,5 / 205,0 мс |

Средний пик этого процесса ниже на 31,94%; это не RAM всей панели и не SLA.

Копия настоящего OVAL JSON (14 365 031 байт) проверена в двух таких же парах:
пик 308 322 304 / 309 882 880 → 257 269 760 / 252 321 792 байт.
Во всех четырёх снимках сохранены все 4161 ID; независимо проверенный
SHA-256 исходника и digest полного снимка без даты экспорта совпали.
На оригинале и в рабочей панели запись не выполнялась.

Предварительный ASCII-замер не учитывал расширение декодированной строки
из-за кириллицы: первоначальный тестовый порог 180 МиБ оказался неверным.
Этот отказ сохранён. Порог регрессии откалиброван до 256 МиБ дополнительного
RSS для данного входа: прежний код повторно дал RED (362 024 960 байт),
новый прошёл. Общий защитный порог MemAvailable 2,25 ГиБ не ослаблялся.

Целевые тесты прошли, включая настоящий PDF со всеми 4000 находками,
концом длинного описания и точным source SHA; исходник не меняется.
Полный набор: 648 web-тестов без пропусков и typecheck прошли. В том же
прогоне сборка была остановлена защитой при MemAvailable 2 378 047 488 байт;
OOM не было. Два повтора с лимитом контейнера 1280 МиБ завершились его OOM
на стадии 15 воркеров; привязка к одному ядру не изменила их число.

## Ограничение воркеров сборки

В установленном Next.js 16.4.1 число воркеров по умолчанию вычисляется из
`os.cpus()`. Квота Docker `--cpus=1` и CPU affinity не сократили их число:
сборка запускала 15 процессов. В `next.config.ts` задано
`experimental: { cpus: 2 }`; схема и потребитель параметра проверены
по установленным исходникам и [документации Next.js](https://github.com/vercel/next.js/blob/canary/packages/next/src/build/index.ts).
Параметр экспериментальный: профиль нужно перепроверять при обновлении Next.

С той же конфигурацией проекта production build и все 144 HTTP-проверки
прошли в 1280 МиБ, CPU=1, без сети, с `NODE_OPTIONS=--max-old-space-size=512`.
Сборка действительно использовала два воркера. TypeScript и статическая
генерация включены; минимальный MemAvailable — 4 210 311 168 байт,
OOM и защитной остановки в этом повторе не было. Лимит heap относится
только к команде проверки, окружение рабочей панели не менялось.
Журналы неудачных попыток сохранены; они не считаются успешной сборкой.

Graphify обновлён в AST-режиме для этого HCP. MCP графов не ответил;
использованы Graphify CLI и Code Graph CLI с точным абсолютным корнем.
Сигнатура функции и вызывающий API проверены по исходникам; прежние
Markdown-anchor замечания графа не относятся к этому изменению.
Приватные замеры, RED/GREEN и журналы:
`~/.local/state/hcp-evidence/pdf-compare-20261116-tg5thy9w/`.

Рабочая панель остаётся на принятом `3c94e6b` / `e0a95d2b`.
Новый образ, CI нового SHA и установка этого среза пока не подтверждены.
Двойной разбор JSON, общий бюджет OVAL/Trivy/JSON, прежние CVE/EOL и
независимая резервная копия остаются открытыми. Рабочие данные и Astra
в этих проверках не изменялись.
