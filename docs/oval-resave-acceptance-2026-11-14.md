# Повторное сохранение источника OVAL — 14 ноября 2026 года

## Причина и изменение

`upsertAstraOvalPolicy` назначал новый `sourceReviewedAt` при каждом сохранении,
в том числе без изменения настроек. Полная конфигурация входит в ключ
подготовленного XML: сохранение неизменного источника делало его копию
недоступной для следующего запуска и требовало новой сетевой загрузки.

Код `d47ff46583587df1dc2803ce71f5344499174a67` сравнивает проверенную нормализованную
конфигурацию с сохранённой внутри существующей SQLite-транзакции. Если все
поля, кроме управляемой сервером даты, равны, возвращается прежняя запись:
даты и журнал не изменяются, проверенный XML остаётся доступен.

При смене URL, SHA-256, области выпуска, архитектур, maxAgeDays,
названия/реквизита источника либо проекции сохраняется обычная новая
конфигурация с серверной датой. Подготовка снова обязательна. Даты клиента
не могут подменить серверную дату. Ключ/формат cache, схема SQLite, API,
валидация XML, TLS и лимит актуальности не менялись; миграция не требуется.

на минуту, шесть прежних тестов прошли. После исправления:

- Все 635 web-тестов без пропусков и typecheck прошли в контейнере 1 ГиБ.

  изменений, восемь изменений настроек и запрет использования базы через
  31 день. Дата генерации XML не обновляется повторным сохранением.
- Production build и 132 HTTP-проверки прошли. Первую сборку остановили:
  неправильный перенос прав из Git-архива мешал переиспользовать слои.
  Затем исходные права восстановили, образ собран из того же Git-коммита.
- В отдельном контейнере с `network=none` проверены реальные HTTP settings

- 13 таблиц и 152 файла рабочей панели после изолированных проверок сохранены.
