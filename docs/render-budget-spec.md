# Общий бюджет генерации отчётов

Состояние: реализовано и проверено локально; [протокол](render-budget-acceptance-2026-11-15.md).

Продолжение пункта общего бюджета памяти в [плане аудита](../tasks/plan.md).

Один экземпляр HCP, включая несколько веб-процессов с общим локальным
`HCP_STATE_DIR`, допускает одновременно два PDF либо один OpenSCAP HTML.
Занятый бюджет возвращает существующий HTTP 429 без очереди. Смерть или
тайм-аут генератора освобождает бюджет только после завершения процесса.
Скачивание сохранённых XML/JSON/DAT не требует этого бюджета.

Реализация: фиксированный Python launcher с блокировками ядра на приватных
файлах, наследуемыми через exec; без БД и новых зависимостей. PDF получает
лимит адресного пространства 1 ГиБ; прежние 32 МБ входа, 12 МБ выхода и
120 с сохраняются. Для HTML сохраняются 1,5 ГиБ, CPU 90 с, 256 МБ выхода,
проверка XML, изоляция окружения и отключение companion-файлов XCCDF.

Проверки: Python unittest для конкурирующих процессов, exec/SIGKILL,
недоверенных файлов и фиксированных команд; существующие Node-тесты обоих
экспортов, typecheck, сборка и изолированное HTTP-тестирование. Большой
PDF сверяется по всем ID и окончанию описаний, ресурсы измеряются под
ограничением контейнера с резервом памяти рабочего компьютера.

Не меняются исходные отчёты, данные рабочей панели, правила Astra,
схема БД или зависимости. OVAL-подготовка, Trivy и чтение больших JSON
остаются следующим срезом; это ещё не общий предел памяти всех операций
HCP. Рабочая версия обновляется только после отдельной полной приёмки.
