# Официальная QEMU Astra Linux 1.7.6.15 — воспроизводимая SSH-проверка

**Исследовательский эксперимент, а не полная приёмка HCP.**

После двух неудачных оригинальных cloud-init образов Astra 1.7.6.UU2
(PR #62, #66) и отдельного VirtualBox OVA (PR #69) появился
альтернативный путь, наиболее подходящий для KVM: **сам официальный
QEMU/KVM-образ производителя**, без конвертации из другого гипервизора.

Источник — Astra Linux UBI Artifactory Storage API, проверено
5 ноября 2026:

- Файл: `alse-1.7.6.uu2-base-qemu-mg15.3.1-amd64.qcow2`
- Размер: **402259968 байт**
- SHA-256: `75d247c79beecd468ab9da777c1c90ca273f20ece748dc2575e7d091eb3e87b4`
- Метаданные:
  https://registry.astralinux.ru/artifactory/api/storage/mg-generic/alse/qemu/alse-1.7.6.uu2-base-qemu-mg15.3.1-amd64.qcow2

**Ограничение:** источник SHA и байты образа происходят от одного
производителя; отдельная независимая цифровая подпись не проверена.

## Эксперимент
Файлы `deployment/tests/verify_astra17_qemu_kvm.py` и
`.github/workflows/astra17-qemu-kvm.yml`:

1. Требуют одноразовый GitHub-hosted runner и приватные временные пути.
2. Загружают строго известный HTTPS URL без редиректов и сверяют
   все байты и SHA-256 перед запуском.
3. Проверяют формат QCOW2 и отсутствие внешнего backing, создают отдельный
   overlay, исходный диск оставляют неизменным.
4. Загружают подлинного гостя через QEMU/KVM, локально перенаправляют
   порт SSH, отдельно закрепляют обнаруженный ED25519 ключ.
5. Для первой проверки **только одноразовой принадлежащей CI виртуальной
   машины** используют документированную Astra UBI фабричную пару `astra/astra`.
   В рабочей HCP эти данные недопустимы; впервые полученный ключ
   не является независимым подтверждением удалённого чужого сервера.
6. Реально наблюдают `ID=astra`, point release `1.7.6`,
   полный build `1.7.6.15`, архитектуру `x86_64`, ядро и наличие
   корректного machine-id. Сырой идентификатор не публикуется.
7. Требуют второе **новое** SSH-соединение к тому же ключу и сравнение
   исходного наблюдения. В артефакты попадает только ограниченный JSON.

**Даже при успешном запуске:** `nativeOpenScap18RulesVerified=false`,
`nativeOval17Evaluated=false`, `nativeRollbackVerified=false` и
`operatorProductionAccepted=false`.

При положительном результате можно отдельно расширять испытания до
штатной HCP инвентаризации, OpenSCAP 18 правил, OVAL 1.7,
контролируемого изменения/отката, восстановления SSH и исходных
доказательств. Не изменять штатные механизмы безопасности Astra,
не объявлять «все CVE найдены» и не закрывать issues #40/#38/#43
по одному smoke-тесту. При неудаче сохранять честный результат.
