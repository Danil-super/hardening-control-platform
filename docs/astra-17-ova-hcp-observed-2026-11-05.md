## Реальный результат

На одноразовом оригинальном образе QEMU/KVM через закреплённый SSH подтверждены `ID=astra`, версия **1.7.6**, сборка **1.7.6.15**, запуск HCP Ansible-сбора системных сведений и инвентаризации **398** установленных пакетов, OpenSCAP **1.3.6** и исходный штатный профиль HCP из **18** правил.

Три проверки на одной ВМ: **14 pass / 4 fail** (baseline), **13 pass / 5 fail** (контролируемое изменение прав `/etc/passwd`), **14 pass / 4 fail** (восстановление исходных прав). Одна проверка действительно сменила состояние `pass → fail → pass`, остальные 17 — без изменений. Подтверждены сохранность исходных прав и повторный SSH к прежнему гостю. Исходные ARF и нормализованные JSON имеют SHA-256 в опубликованном доказательстве, но сами ARF не распространяются.

## Ограничения, без преувеличений

Это **не** полное исследование Astra OVAL 1.7 и не подтверждение всех CVE; не доказаны независимая подпись производителя, производственное подключение через HCP `assetId/generation`, комплексный rollback ОС и firewall, применимость к `adv/max`, эксплуатационная приёмка Ubuntu-контроллера. В исходном доказательстве правильно установлены `fullNative18RuleAcceptance=false`, `ovalEvaluationPerformed=false`, `hardenedProdReady=false`. Лабораторный ansible-core 2.17.14 работает с Python 3.7 гостя, но **снят с поддержки** и не рекомендован для production.

Исходный исторический JSON намеренно **не переписан**: общие строковые поля `experiment` и `limitations` унаследованы от SSH-only smoke и не отражают успешно выполненные три стадии в `nativeHcp`. Отдельный коммит PR #72 исправляет метки будущих запусков с дополнительной проверкой доказательств. Успех исходного CI не относится автоматически к последующим коммитам.
