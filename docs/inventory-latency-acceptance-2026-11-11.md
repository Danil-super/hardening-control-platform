# Задержка списка хостов — 11 ноября 2026

Подтверждён и устранён один источник пауз из предыдущего нагрузочного прогона:
при отображении пяти хостов HCP последовательно запускал пять процессов
`ansible-inventory`. Медиана холодного запроса снизилась с 1170 до 241 мс.
Это ускорение конкретного сценария, а не доказательство устранения всех
исторических выбросов до 2,24 секунды.

Код: `e0db79bf77cb1fe6991869396ae40ef951201847`.
Образ: `sha256:a4b06e3643b3c5a0ade9d2229a1772e6c062afcc34a35f925a883a30944b4c9f`.
Числа и SHA первичных файлов: [очищенный протокол](evidence/inventory-latency-2026-11-11.json).

## Как установлена причина

В отдельном HCP использована копия только испытательных данных предыдущего
прогона: пять Ubuntu-активов и 22 сохранённых отчёта, включая подготовительные.
Удалённые ВМ оставались выключенными. Новые SSH-подключения, аудиты и изменения
firewall не выполнялись. Основная панель продолжала работать отдельно.

Оба образа ограничены одинаковыми 2 CPU / 4 ГиБ. Перед каждым из трёх циклов
выдержаны 5,2 секунды для истечения кеша. В цикле запрошены холодный и тёплый
GET /api/ansible/hosts, список отчётов и корреляция первого хоста. Параллельный
поток делал GET /login с паузой 30 мс между завершёнными запросами.

Временный Node preload измерял длительность настоящих `execFileSync`, время
HTTP-запросов и задержку event loop. Он записывал только имя команды, путь
запроса и время; параметры, заголовки, пароли и тела ответов не записывались.
В рабочем образе эта диагностика не включена.

Во всех трёх холодных запросах прежнего образа было по пять синхронных
вызовов; они занимали почти всё время запроса. Тёплый запрос не запускал CLI.
Это соответствует блокирующему поведению, описанному в
[документации Node](https://nodejs.org/docs/latest-v24.x/api/child_process.html#synchronous-process-creation).

## Изменение и проверки безопасности

Только resolver для отображения теперь получает нативный `--list` один раз
и сохраняет короткоживущий набор хешей подключений. Формат и синхронный
контракт вызывающих функций сохранены. TTL по-прежнему 5 секунд; хеши самого
INI и ограниченного набора host_vars/group_vars проверяются до использования
кеша. Правки переменных учитываются сразу, даже до истечения TTL.

Приоритет переменных по-прежнему определяет Ansible с тем же --playbook-dir;
переписывания правил его YAML/INI-парсера нет. Важность этого параметра
подтверждает [официальная инструкция inventory](https://docs.ansible.com/ansible/latest/inventory_guide/intro_inventory.html#organizing-host-and-group-variables).
При сбое CLI, некорректном JSON или недопустимом подключении остаётся
unresolved. Старая идентичность не используется как запасной ответ.
Общий stdout ограничен 4 МиБ, время CLI — 15 секундами; shell не запускается.
Кеш содержит только хеши подключений. Настоящее выполнение аудитов и
изменений продолжает использовать отдельный свежий resolver и проверку SSH.

Новая регрессия сначала воспроизвела пять запусков вместо одного. После
исправления проверены один запуск на пять хостов, нативные приоритеты
переменных, немедленная инвалидация после правок host_vars/group_vars,
изолированная ошибка одного endpoint и отказ от прежнего значения при
неисправном выводе/сбое процесса. Прошли 27 профильных тестов с нативным
Ansible на управляющей Ubuntu, production build, 620 web и 125 HTTP в образе.

Медиана холодного запроса уменьшилась на 79,41%; диапазоны трёх повторов не
пересекаются. Тёплые запросы остались примерно на прежнем уровне, 5–6 мс;
улучшение p95 не заявляется. Один синхронный вызов остаётся: это устранение
повторной работы на каждый хост, а не полностью неблокирующая архитектура.

В Chromium финального образа проверены пять строк хостов, неизменные
количества отчётов 8/5/5/2/2, корреляция, 401 и 403. На 390 и 1440 пикселях
нет JS-ошибок и переполнения страницы. Дополнительная проверка 320 пикселей
обнаружила documentWidth=349 и на прежнем, и на новом образе; этот отдельный
дефект страницы «Хосты» остаётся открытым. Он не объявлен успешной приёмкой.

Финальный образ установлен локально; сохранены 13 проверяемых таблиц, 101 файл
отчётов, окружение и mounts. Временные контроллеры остановлены. Обновлён
локальный тег Compose. Runtime/зависимости повторно использованы из принятого
образа: чистой пересборки всех зависимостей и нового GitHub CI в этом этапе нет.

Большие OVAL/JSON, запуск параллельных сканеров и RPS-нагрузка повторно не
профилировались. HTTPS, внешние anchors/DR и подпись оператора остаются открытыми.
