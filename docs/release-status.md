не означает их публикацию, успешный CI или обновление работающего контейнера.

## Контракты кандидата

- Сохранённая OVAL-политика передаёт `evidenceProjection` в штатный запуск.
  При отсутствии поля используется bounded; explicit detailed остаётся допустимым.
  Bounded сокращает повторное вложение XML, но сохраняет каждый ID и точный статус.
- Новые bounded/detailed определения используют объект `platformApplicability`.
  Чтение старой строковой формы сохраняется; unknown/foreign не становятся proof.
- Подтверждение устранения требует того же источника, исходного определения,
  актива и поколения подключения. Смена базы не означает исправления CVE.
- Неполный, дублированный или неизвестный результат не получает статус complete.
  Проверка согласованности JSON не удостоверяет подлинность производителя.

## Локальная проверка кандидата, 6 ноября

На отдельной копии исходников прошли типизация, Next production build,
**560 веб-регрессий**, **350 Ansible/Python-регрессий**, **233 deployment-регрессии**
и **75 HTTP-проверок**. HTTP проверяет сохранение OVAL-политики через перезапуск,
подтверждение администратора, передачу bounded исполнителю и публикацию JSON
с verified asset binding. Реальные сканеры в этом HTTP-прогоне заменены
явными фикстурами; новый сетевой аудит или firewall-изменение не выполнялись.
Команды, окружение, причины повторов и ещё открытые критерии: [задачи](../tasks/todo.md).
Эти проверки не являются GitHub CI единого RC SHA или операторским E2E.

## Последовательность приёмки

1. Локальные регрессии, типизация, production build и изолированный HTTP.
2. Зафиксированный RC SHA и необходимая GitHub CI-матрица именно этого SHA.
3. Обновление выделенного стенда и настоящий операторский E2E.
4. Независимое восстановление, desktop/mobile и итоговый пакет диплома.

Автоотмена CI относится только к устаревшим прогонам одного PR и workflow.
Push main и ручные прогоны имеют собственный run ID и не отменяют друг друга.
Состав проверок и их триггеры сохранены. Дополнительное разделение быстрых и
дорогих проверок требует отдельной проверки required checks перед публикацией.

## Ограничения, которые сохраняются

Legacy Ansible для Python Astra 1.7 находится вне поддержки upstream.
Совместимость исполнения не равна поддерживаемости или production-безопасности.
Доверие к CVE-источникам, backports, сетевой perimeter/rate-limit, зависимости,
image digests и нагрузка 1/3/5 хостов требуют отдельных проверок.
Автоматический rollback ограничен поддержанными UFW/firewalld; он не является
универсальным восстановлением ОС. Все уязвимости обнаруженными не объявляются.
