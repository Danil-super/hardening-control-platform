## Контракты и оригиналы

- Сохранённая OVAL-политика передаёт `evidenceProjection` исполнителю.
  По умолчанию bounded; detailed допустим явно. Компактная форма сохраняет
  каждый ID и точный результат.
- Новая `platformApplicability` — объект; старая строковая форма читается.
  Unknown/foreign, неполные, дублированные и неизвестные результаты не дают proof.
- Подтверждение устранения требует false исходного определения, той же базы,
  актива и поколения подключения. Смена базы не означает исправления CVE.
- HCP сохраняет оценённый source XML и ARF/OVAL results до очистки staging в
  `reports/.raw-evidence/<report-id>/`: каталоги 0700, файлы 0600. `rawEvidence`
  связывает пути, размеры и SHA с исходным JSON и его asset binding.
- Нет оригинала — новый отчёт partial; ссылка, неверный тип/размер или checksum
  останавливают публикацию. Копирование потоковое, оригиналы входят в backup.
  Проверка сохранения настоящим OpenSCAP на синтетическом source — отдельная
  фикстура, включая подставленную Astra identity.
- Origin учитывает forwarded authority/protocol только при явном доверии
  `HCP_TRUSTED_TLS_PROXY`. Учтена переписанная Next.js схема `nextUrl`.
  Production HTTP-регрессия воспроизводила прежний 400 и требует 403 до dispatch;
  положительный HTTPS Origin за доверенным прокси также проверен.

Исторические оригиналы и прежний ошибочный верхний OVAL-флаг не исправлялись
задним числом. Подлинность производителя и полнота CVE не выводятся из JSON.

## Проверка и локальное обновление

На предыдущем `e71232e` прошли 350 Ansible/Python и 233 deployment-регрессии,
пакетные контракты, 79 HTTP-проверок и пять native Trivy-контролей через HCP.
Контроли Trivy используют явно синтетические инвентари Ubuntu: проверяются
уязвимая/исправленная версия, multiarch, epoch и неизвестный поставщик.
Это не новые сканирования пользовательской Astra. HTTP-фикстуры теперь явно
изолируют унаследованный modern Ansible; исходный неуспех и повтор сохранены.

Проверен штатный entrypoint с `npm start`, UID node и новым входом/выходом.
Офлайн-переводчик запущен на общедоступном типовом тексте в контейнере без сети.
GitHub CI дополнительно выполнил типизацию, production build и веб-регрессии.

При последнем обновлении рабочей панели до `eacd302` сохранён свежий
согласованный SQLite snapshot.
Совпали 13 таблиц кроме служебных сессий, все 46 исходных файлов доказательств,
HMAC-head и 201 событие; активных отчётов осталось 15. Проверочный cookie
пережил обновление, новый вход/выход и запрет replay прошли. Прежний образ,
полная холодная копия и приватные снимки сохранены вне Git/GitHub.

При предыдущем обновлении до `e71232e` первая попытка автоматически вернула
старый образ из-за двух пустых proxy
ENV-ключей в нём, отсутствующих в новом. До повторного переключения проверено
ожидаемое окружение. Допущена только эквивалентность empty/unset этих ключей
при отсутствии непустых proxy; все параметры HCP и секреты совпали.
Финальное переключение прошло, контейнер healthy. Сеть, команда loopback и
persistent mounts сохранены; новый SSH к недоступной Astra не выполнялся.

Исправления: APT 2.6.2, libpcre2, liblzma и tzdata обновляются даже поверх
кэшированной базы; до обновления APT отключён его retry-путь.
[CVE-2026-109518 исправлена Debian в APT 2.6.2](https://security-tracker.debian.org/tracker/CVE-2026-109518).

Обновление Trivy также описано в [официальном релизе](https://github.com/aquasecurity/trivy/releases/tag/v0.76.2).

Открыты остаточные advisory, Python/install tools и политика поддержки старых
целей. Upstream Ansible 2.14 имеет [EOL 20 мая 2024 года](https://docs.ansible.com/projects/ansible/latest/reference_appendices/release_and_maintenance.html#ansible-core-support-matrix);
Debian backports учитываются отдельно. Primary сохраняет 2.14.18 и отдельный
modern 2.21.5, выбранный по подтверждённому Python цели. В hosted Astra CI
2.17.14 также явно обозначен EOL. APT-артефакты ещё не закреплены:
повторная сборка зависит от репозиториев. Нагрузка 1/3/5
реальных хостов и операторское решение по остаточному риску не приняты.

Установленный `eacd302` закрепляет Node/Python OCI digest и
полный состав трёх tool venv в `deployment/requirements/*.txt`. Установка
требует SHA-256 и binary wheels, а `pip check` проверяет зависимости. Старые
pip 23.0.1 / setuptools 66.1.1 в SSH/translation заменены на 26.2.2 / 84.2.1.
Предварительный образ прошёл проверку точного состава трёх окружений,
modern Ansible localhost ping, SSH CLI/offline lookup, настоящий офлайн-перевод,
79 HTTP и 8 unit проверок. Финальный образ собран из зафиксированного коммита:
его OCI revision и config/layers Docker archive проверены, байты трёх lockfile
совпали с Git. На нём повторены exact closure/pip check, modern localhost ping,
офлайн-перевод и 79 HTTP. SHA-256 архива:
`1668c133b1f14f95eef4c71cbafd94dee9baff4371870003d887f30ef08f790e`.
В изоляции четыре проверки отклонили отсутствующий/неверный hash,
незакреплённую транзитивную зависимость и изменённый wheel. Контрольное снятие
require-hashes допускает пакет без hash, то есть тест различает этот обход.

Тот же Trivy 0.74.0 и неизменная база дали **674 строки вместо 696**:
Python 30 → 8, остальные категории совпали. Удалены 14 строк pip и 8 setuptools;
новых нет. Остаток — 130 HIGH и 11 CRITICAL по меткам источников, 435 различных
идентификаторов. Это не утверждение об эксплуатируемости. Финальный образ дал
тот же точный набор записей. CycloneDX 1.7 SBOM содержит 964 компонента,
1 134 896 байт; SHA-256:
`5033543e1b0e39196f3a0686888870a8fd2666b1a9f8cbf18753eaac7256dfaa`.
Отчёт уязвимостей сохранён отдельно, оба артефакта созданы без сети и без
подключения пользовательского runtime. Восемь оставшихся Python-записей
относятся к msgpack/setuptools/urllib3 из `pip/_vendor/vendor.txt` в образе;
обновление отдельного top-level setuptools эти копии не заменяет.
Это установленные местоположения компонентов, не доказанная достижимость
уязвимого кода из HCP; разбор применимости остаётся открытым.
APT продолжает использовать обновляемые репозитории, поэтому полного
побайтового воспроизведения сборки пока нет. Порядок обновления locks:
[инструкция поставки](../deployment/README.md#закреплённые-зависимости-образа).

## Эксплуатационные ограничения

- Фактический listener после обновления — `127.0.0.1:3000`, используется прежний
  host-network override. До переключения проверено 19 адресов управляющей
  машины из отдельного сетевого пространства: порт 3000 недоступен. Это scoped
  проверка локального стенда; публичный HTTPS, rate limit и внешний peer review открыты.
- `main` защищена: PR, strict checks `web`, `ansible`, `container`, `lab` от
  GitHub Actions (app 15368), включая администратора; force push и удаление
  запрещены, обсуждения должны быть закрыты. Обязательных одобрений — 0;
  фактический peer review релиза остаётся отдельным условием.
- В RC общий `Required platform checks` всегда проверяет четыре результата;
  failed/cancelled/skipped/пустое значение дают отказ. Проверены 22 случая и
  mutation bypass. [Целевая политика общего gate](../.github/branch-protection-main.json)
  применяется после включения workflow в main, чтобы не заблокировать PR из
  прежней main без этого job. Текущая main исходников не изменялась.

## Отдельная Ubuntu и оставшаяся приёмка

На `1306a2a` выполнен настоящий перенос runtime/settings/image в Ubuntu 24.04.5
KVM на том же компьютере, 2 vCPU / 4 ГиБ. Образ Ubuntu проверен GPG/SHA, SSH-ключ
сверён с консолью, рабочая сеть закрыта до переноса секретов. Внешние pins
manifest/HMAC удержаны вне копии. Исходные 14 таблиц и 201 событие совпали;
скопированный непросроченный cookie после отзыва получил 401, новый вход/выход прошли.

53 HTTP-проверки охватили PDF на 15 исторических исходниках и архивный цикл.
Три страницы PDF с кириллицей просмотрены; повторное скачивание, snapshot и
manifest совпали. Полное восстановление архива вернуло 27 отчётов и 114 записей
журнала; PDF остался доступен, удаление его источника отклонено с 409.

остались побайтно прежними. Попытка с 2 ГиБ была ниже минимума и получила V8 OOM;
4 ГиБ прошли, PDF занял 4,911 с, peak cgroup около 2,14 ГиБ. Это один dataset,

config/manifest digest разных Docker stores сверены по config и 26 RootFS layers.
Процедуры: [backup/restore](backup-restore.md), [readiness](operator-restore-readiness.md).

Браузерный smoke на `1306a2a`: девять страниц в Chromium 147 на двух размерах,
