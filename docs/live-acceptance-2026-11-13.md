# Повторная проверка на Astra — 13 ноября 2026 года

Уточнение последующего этапа: проверка архитектуры пакетов в PDF ниже была
недостаточной. Коллектор использует `arch`, прежний экспорт его не читал.
Имя/версия и количество пакетов подтверждены; ошибка архитектуры обнаружена
и исправлена отдельно. См. [строгую повторную сверку](final-controls-acceptance-2026-11-13.md).

Проверена ранее привязанная Astra Linux SE 1.7.6 с Python 3.7.3.
SSH fingerprint и идентичность совпали, модуль Ansible выполнился с sudo/root.
Пароль использовался разово в памяти и не сохранялся. Аудиты выполнялись
последовательно; настройки ОС и firewall не менялись.

## Найденное исправление

В PDF инвентаризации отсутствовал список пакетов: экспорт читал
`packageInventory.packages`, хотя коллектор сохраняет `packages` в корне JSON.
Коммит `a9e7fb5ab77c5552bb9e1d0be495a19df3b07fe9` читает фактическое поле,
сохраняет поддержку прежнего вложенного формата и прежнее ограничение
экспорта полями имени, версии и архитектуры.

Регрессия воспроизведена тестом до правки; после неё прошли шесть PDF-тестов,
все 634 web-теста, production build, typecheck и 129 HTTP-проверок.
На отдельном экземпляре нового образа проверены **все 2980 сочетаний имени,
версии и архитектуры** настоящего отчёта. PDF — 163 056 байт;
SHA исходного JSON `a6e6810eb577f464a51d620e1407f1f6d345767b3ceb1e08fa1ff325e24249cf`.
Исходный JSON не переписывался; повторный аудит для исправления PDF не нужен.

Образ кандидата:
`sha256:33368bbd5daca8e66a351ef7a213052bba6d07ae8cc6253d26eb2e95ae3809b8`.
Добавление OCI-меток не изменило RootFS. Совпали байты dpkg status, SSH,
libxml2, SQLite и GLib с предыдущим образом. Это не новый полный Trivy scan
и не закрытие прежних CVE. Итог установки и CI фиксируется в
[актуальном паспорте](release-status.md).

Кандидат установлен с сохранением окружения, mounts, 13 таблиц и 135 файлов.
Через кнопку установленного сайта скачан PDF: все 2980 записей сверены повторно,
JS-ошибок и 5xx нет. GitHub этого SHA — 20/20 workflow и 28/28 checks; первый
запуск Astra 1.8.6 остановился на сетевом тайм-ауте официальной OVAL-базы,
повтор только упавшего задания на том же SHA прошёл.

## Память и границы

Минимальный **зафиксированный** MemAvailable во время реальных проверок —
1 382 551 552 байта (1,29 ГиБ); шесть выборок ниже 2 ГиБ за 15 секунд.
Порог не удержан. В прочитанном журнале ядра этого интервала OOM не обнаружен.
Система использовала почти весь swap; полный OVAL не запускался из-за этого
наблюдения. Для нового тяжёлого прогона нужен больший свободный запас памяти.

Первоначальный большой провальный assert упёрся в лимиты проверочного процесса;
регрессионный fixture уменьшен до трёх записей, а полный набор проверен отдельно
по настоящему PDF из 2980 строк. Успешные web-регрессии ограничены 1 ГиБ,
сборка — 2 ГиБ без дополнительного swap; их мониторинг не пересёк порог 2 ГиБ
MemAvailable. Результаты не задают универсальный минимальный RAM для HCP.

Подготовлен новый согласованный локальный backup с этими отчётами. Пауза
панели — 44,393 секунды; после запуска таблицы и файлы совпали.
Manifest SHA-256: `f8800244a69b507d24fa1ea5857725344ae04bfe7387e087c4e1056f1028f18d`.
Это снимок перед установкой исправления, не независимое внешнее хранение.

Снимок фактически восстановлен на кандидате в отдельной внутренней сети:
проверены исходные файлы, SQLite, HMAC 285, все 43/41 записи списков, XML/PDF,
вход, CSRF и отзыв ранее действовавшей cookie. SSH из копии к Astra был
недоступен. Исходная панель сохранила данные; копия и её сеть удалены.
Для архива с двумя старыми JSON по 323 МБ лимитов 1 и 1,5 ГиБ оказалось
недостаточно. Успешная копия имела лимит 3 ГиБ без дополнительного swap;
минимальный MemAvailable в её первом HTTP-цикле — 3 533 869 056 байт.
Это отдельное измерение, не гарантия памяти для любого набора отчётов.

Обновлённый переносимый комплект — `delivery-kit-current/` в каталоге
первичных материалов. Он содержит образ кандидата, исходники, утилиты,
закрытые настройки и проверенный снимок перед обновлением со свежими
результатами. Manifest SHA-256:
`80db7df2722c16e72b388693fd03dbf193582e27075ab67f0f974ab1d5839173`.
Неизменные локальные архивы разделяют байты через hardlink; комплект не является
независимой копией. После установки новый cold backup этим не заявляется.

Новый цикл изменения/отката firewall, новый полный OVAL и новый Greenbone
на операторской ВМ не выполнялись. OpenSSH остаётся отложенным пунктом.
Предыдущие результаты не выдаются за новые запуски.
В задачах также оставлена неточная подсказка инвентаризации Astra, предлагающая
Trivy. Итоговый отчёт корректно сообщает о неподдерживаемой ОС и необходимости
OVAL; подсказка не подтверждает доступного CVE-покрытия Astra через Trivy.
