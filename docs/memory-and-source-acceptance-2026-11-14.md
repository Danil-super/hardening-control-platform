## Подтверждённый источник расхода памяти

Холодное чтение двух архивных JSON примерно по 323 МБ создавало один
долгоживущий worker. До изменения полный вызов API чтения 89 отчётов достигал
RSS 2 098 696 192 байт; отдельный исходный прогон при Docker limit 1,5 ГиБ
завершился cgroup OOM (137). Ошибочный первый запуск без права чтения приватных
файлов исключён из сравнения, его журнал сохранён.

Теперь существующий worker читает пакеты суммарным размером до 64 МиБ и
завершается между ними. Один большой исторический файл обрабатывается целиком;
исходники, нормализация, зависимости и порядок результатов не сокращаются.
Синхронные вызовы внутри транзакций сохраняют прежний контракт.

Три прогона настоящих API на тех же 89 файлах дали максимальный RSS
1 414 705 152 / 1 415 057 408 / 1 414 651 904 байта: около 1,32 вместо 1,95 ГиБ,
снижение примерно на 33%. Каждый прошёл под лимитом 1,5 ГиБ без swap/OOM.
Все поля 89 сводок и все зависимые связи побайтно равны результату исходного
API. Это измерение конкретного чтения, не бюджет всего процесса HCP и не SLA.
Все прежние эпизоды падения MemAvailable этим не объяснены.

Изолированный браузер установленной панели проверил 41 архивный и 48 активных
отчётов, переходы архив → активные → хосты, загрузку списка и кнопку настройки.
Ошибок JavaScript/HTTP 5xx не было; минимум MemAvailable — 8 345 780 224 байта.
Проверка выполнялась до добавления двух новых контрольных отчётов этого этапа.
