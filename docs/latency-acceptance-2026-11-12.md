# Задержки страницы хостов и архива — 12 ноября 2026

Область: максимум три тестовых хоста, настольный Chromium, сохранение исходных
отчётов и доказательств. Пять хостов исключены по решению оператора.
Числа и хеши: [очищенный протокол](evidence/latency-2026-11-12.json).
Статус установки и оставшиеся этапы: [release-status](release-status.md).

## Причины и изменения

Нативный `ansible-inventory --list` при отображении хостов блокировал основной
поток. В `082d0fd` запрос переведён на асинхронный запуск; одновременно пришедшие
запросы используют один результат. Приоритеты переменных определяет прежний
Ansible. Сигнатура файлов, TTL 5 секунд, лимиты CLI и отказ от старой идентичности
при ошибке сохранены. AsyncLocalStorage ограничивает снимок текущим запросом.

После этого отдельный повтор на копии настоящего архива выявил вторую причину:
два исторических JSON по 323 МБ читались и разбирались синхронно. Первый список
архива задерживал соседний запрос на несколько секунд. Предпросмотр зависимостей
затем повторно разбирал все исходные деревья ради трёх полей ссылок.

В `05b2c5b` чтение, JSON.parse и нормализация холодных сводок выполняются одним
фоновым Worker. В основной поток возвращаются только компактные сводки и ссылки.
Используется тот же код нормализации; копии алгоритма оценки риска нет.
Очередь не запускает несколько тяжёлых читателей одновременно. После чтения
временный heap освобождается завершением Worker. Предел old generation —
1536 МиБ, ожидание — 60 секунд; NODE_OPTIONS может переопределить предел V8.
В парном опыте использовался прежний --max-old-space-size=2048 для обоих
вариантов, Дополнительные три повтора с обычными параметрами тоже прошли: те же
ответы API, максимум соседнего запроса 95,00 / 24,22 / 58,16 мс.
Это не общий предел памяти процесса: буферы
и остальные части Node учитываются отдельно. См. [Worker resourceLimits](https://nodejs.org/docs/latest-v24.x/api/worker_threads.html#new-workerfilename-options).

Сигнатуры inode/size/mtime/ctime проверяются после ожидания. Изменившийся файл
прерывает запрос, сбой Worker не превращается в пустой успешный отчёт. Будущие
и некорректные даты пересчитываются при следующем чтении. Ссылки учитываются
для всех режимов, включая неизвестные; приоритеты типов зависимостей сохранены.
Синхронные операции удаления и их блокировки остались отдельным контрактом.

На сборке Next обнаружена его подмена workerData у упакованного Worker;
использован нативный конструктор через createRequire. Добавлены HTTP-проверки
холодного списка API, страницы, хостов и предпросмотра зависимостей. Общий
компилятор вынесен из test-helper в scripts. CI выявил пропущенное копирование
этого файла в стенд Trivy; `89b25ac` добавляет его и фильтры запуска workflow.
В режиме next dev после правок серверных нормализаторов требуется перезапуск;
production build всегда собирает Worker заново.

## Парные измерения

В первом опыте использованы одинаковые 2 CPU / 1536 МиБ, копия испытательного
runtime и исторический OVAL с 4135 находками. Выполнено по три холодных повтора.
У `/hosts` синхронных вызовов inventory стало 0 вместо 6 за повтор. Медиана
максимума соседнего /login: 422,28 → 307,48 мс. Холодный список хостов стал
медленнее: 400–455 → 524–625 мс; общего ускорения списка не заявляется.
Диапазоны event loop пересекаются, устойчивого процентного улучшения нет.
Ответ хостов во всех шести повторах побайтно одинаков.
Проверены 18 загрузок XML, SHA входных данных 18 PDF и все ID в 6 полных PDF.

Во втором опыте использована отдельная копия настоящего runtime: 33 активных
и 41 архивный отчёт, всего 116 файлов. Перед каждым повтором процесс запускался
заново, одинаковые 2 CPU / 3 ГиБ, swap контейнера запрещён. Параллельно запрашивались
/login и список заданий. Это сравнение `082d0fd` и исправления читателя.

Все четыре ответа API во всех шести запусках побайтно одинаковы. Все 116
исходных файлов сохранены, cgroup OOM отсутствует.

## Проверки и границы

Прошли 630 тестов, production build и 129 HTTP-проверок в штатном контейнере.
На рабочей Ubuntu полный прогон PDF не прошёл из-за отсутствующего ReportLab;
этот результат не объявляется успешным, PDF проверены в контейнере.
Новые регрессии покрывают уступку event loop, конкурентное холодное чтение,
ссылки неизвестного адаптера, некорректные даты, изменение/удаление файлов,
недоступность Worker и восстановление после ошибки.

На `082d0fd` завершены три настоящих Lynis и три SSH-аудита с пересечением
выполнения; DAT/JSON, коды Lynis, индекс и PDF проверены. Настольные переходы
и reload проверены при трёх активных заданиях. На финальном читателе повторены ещё три Lynis и три SSH-аудита; все завершены,
оригиналы и 7 PDF (включая исторический OVAL) проверены. При трёх заданиях
переходы и reload прошли на 1280/1440/1920, без JS-ошибок. Выполнены 3049
успешных read-запросов. Офлайн подтверждены 32 HMAC-события, прежний префикс
26 и все 45 прежних файлов испытательного набора сохранены. Тестовые ВМ и HCP
выключены; рабочие 119 файлов и 13 таблиц не изменялись. Пик cgroup финального
HCP не сохранён до его остановки; OOMKilled=false, ошибки аудитов отсутствуют.
Минимум доступной памяти за весь этап — 2,94 ГиБ, порог 2 ГиБ не сработал.

Перед обновлением сделан полный холодный backup нынешнего рабочего образа,
runtime и настроек, уже со всеми 119 файлами. Bundle прошёл проверку manifest;
панель после паузы 46,99 секунды вернулась healthy, хеши данных совпали. Это
локальная копия на том же компьютере. Она восстановлена из сохранённого
образа в отдельный runtime: 34 активных отчёта, 277 HMAC-событий, вход/401/403
и отзыв контролируемого cookie проверены; исходные данные не изменились.
Отдельного внешнего DR этот шаг не подтверждает.

Исходный редкий максимум 6,96 секунды из предыдущей нагрузки прямо не
воспроизведён. Найдены и исправлены две конкретные блокировки, но все возможные
задержки не объявлены устранёнными. Полное открытие старых JSON и синхронные
пути транзакций остаются отдельной областью измерений. Три одновременных
полных OVAL-сканирования Astra не выполнялись. Зависимости образа повторно
использованы из принятого runtime; новой локальной чистой установки всех пакетов
в этом этапе нет. Внешнее хранение backup/anchors, DR, HTTPS, подпись оператора
и ранее зафиксированные CVE этим изменением не закрываются.
