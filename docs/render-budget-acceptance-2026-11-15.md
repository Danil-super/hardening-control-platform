# Общий лимит PDF и HTML: локальная приёмка

Реализован следующий срез [плана](../tasks/plan.md) по
[контракту](render-budget-spec.md). Пока не установлен на рабочем сайте:
там остаётся принятый `cb8df37` / образ `17bb5e9c`.

## Поведение

Два PDF либо один OpenSCAP HTML разделяют бюджет через приватные файловые
блокировки ядра. Он общий для процессов с одним локальным `HCP_STATE_DIR`.
Очереди нет: лишний экспорт возвращает существующий HTTP 429. Блокировки
наследуются через `exec`, освобождаются при завершении генератора, включая
SIGKILL; файлы блокировок не удаляются. Параллельные независимые хранилища
не образуют общий бюджет.

Новый launcher запускает только фиксированные PDF / OVAL / XCCDF команды.
PDF ограничен адресным пространством 1 ГиБ и CPU 115 с; прежние вход
32 МБ, выход 12 МБ и wall timeout 120 с сохранены. HTML сохраняет прежние
1,5 ГиБ / CPU 90 с / выход 256 МБ, XML-проверки, приватный снимок,
изолированное окружение и отключение companion-файлов XCCDF.
Новые зависимости и изменения БД не понадобились.

## Проверки

Два новых Node-сценария сначала воспроизвели неверную классификацию занятости
как ошибки экспорта. После исправления прошли все 643 web-теста, typecheck,
production build, 144 HTTP-проверки и 380 Ansible/Python-тестов без пропусков.
Семь новых Python-тестов проверяют несколько процессов, `exec` через
настоящий `prlimit`, SIGKILL, освобождение после отказа/ошибки exec, whitelist
CLI, приватные права, симлинки, hardlink и FIFO без зависания.

Через production HTTP с внешним держателем блокировки проверены:

- HTML исключает обычный и итоговый PDF, а также другой HTML: HTTP 429.
- Исходный XML побайтно доступен, список заданий отвечает.
- Один PDF исключает HTML, но допускает второй PDF.
- После освобождения оба вида PDF формируются и скачиваются.
- Отказ не создаёт незавершённый итоговый отчёт в хранилище.

Настоящий сохранённый ARF обработан обоими способами: HTML побайтно одинаков,
276 389 байт, все 18 ID правил присутствуют. Исходный XML не менялся.
Для PDF использован вход 31 849 102 байта: сформировано 6 795 843 байта,
сверены все 10 000 CVE и 10 000 окончаний длинных описаний. Пик RSS
Python — 234 917 888 байт при лимите адресного пространства 1 ГиБ.

## Измерение конкуренции

Три настоящих Node-процесса синхронно запускают по два PDF, каждый с
4000 записями. Прежний код взят из `262c498`; новый код отличается только
рассматриваемым срезом. Одинаковый контейнер: один CPU, RAM и memory+swap
по 2 ГиБ, без сети. Замер каждые 30 мс суммирует RSS процесса измерения и
его потомков; это не RSS всего компьютера. Занятые запросы повторяются
после завершения первой волны.

| Вариант | Одновременных Python | Пик RSS, два прогона | Итог |
| --- | --- | --- | --- |
| Прежний лимит на процесс | 6 | 678 322 176 / 681 050 112 байт | 6 PDF |
| Общий лимит | 2 | 367 214 592 / 369 717 248 байт | 6 PDF после повтора |

В этом сценарии пик ниже примерно на 46%. Во всех 24 PDF сверены полные
наборы 4000 CVE, включая последний ID; каждый PDF — 674 841 байт.
Измерение не доказывает предел RAM любого отчёта или общий SLA.

## Ресурсы и границы

Все контейнеры изолированы от рабочей БД, inventory и настроек Astra.
Собственные нагрузки останавливаются при MemAvailable ниже 2,25 ГиБ;
во время полной серии/сборки минимум был 3 216 519 168 байт, OOM и
защитной остановки не было. Swap компьютера не изменялся.

Приватные исходные срезы, журналы, измерители и receipts сохранены в
`~/.local/state/hcp-evidence/render-resources-20261115-cjtpb_7t/`.
Graphify обновлён для корня HCP; Code Graph и связи вызовов проверены
по исходникам. Замечания Code Graph о прежних Markdown anchors и
дубликатах не относятся к изменению; внешние API не менялись.

Это локальная проверка кода поверх принятого образа. Полный Dockerfile,
GitHub CI точного нового SHA, новый scan/SBOM, restore и установка ещё
не подтверждены. OVAL-подготовка, Trivy и чтение больших JSON пока не
входят в этот бюджет. Прежние CVE/EOL и независимое хранение остаются
открытыми.
