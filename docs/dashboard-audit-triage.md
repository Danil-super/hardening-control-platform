# Оперативная сводка HCP: подтверждённая область проверок и находки

## Цель

На странице «Обзор» специалисту доступны фильтры по состоянию доказательств
и раздельное распределение наблюдаемых находок по критичности. Эти элементы
помогают выбрать очередной хост для разбора и **не** создают сводный рейтинг
«защищённости», процент контроля всех CVE или соответствия нормативам.

## Откуда берутся числа

Источник — текущий авторизованный `GET /api/ansible/hosts`, поле
`riskSummary`. Контроллер формирует корреляцию последних применимых отчётов
каждого инструмента и профиля с учётом времени и привязки к идентичности актива.
Диагностические факты, передача SBOM и необработанный инвентарь не считаются
завершённым аудитом.

Состояния не пересекаются:

- **Свежие:** есть текущие доступные доказательства в наблюдаемой области,
  отсутствуют известные проблемы счётчиков, неполные/устаревшие источники и
  исключения по идентичности. Это **не** полное CVE-покрытие.
- **Требуют уточнения:** свежие частичные данные, противоречия в счётчиках,
  исключённые по идентичности источники либо отсутствие достоверной сводки
  (`unknown_evidence`). Последнее не означает, что аудит вообще не выполнялся.
- **Без свежего аудита:** нет сохранённых проверок безопасности либо все
  предыдущие результаты утратили актуальность.

Сумма трёх категорий равна числу подключённых хостов. Фильтры «Все / Свежие /
Требуют уточнения / Без свежего аудита» влияют только на отображение таблицы;
они не начинают новые задания и не меняют состояние сервера.

## Диаграмма уровней критичности

«Критические», «Высокие», «Средние», «Низкие» и «Без оценки» — это количества
наблюдений **по текущим доступным свежим источникам**, суммированные по
хостам; это не число уникальных CVE на всём объекте. Наблюдения с неизвестной
критичностью не занижаются до low. Для устаревшего, отсутствующего или
противоречивого источника график не превращает старые значения в текущие.

Если нет подтверждённых свежих источников, диаграмма объясняет отсутствие
данных, а не показывает зелёный «0 угроз». При нулевых наблюдениях из доступных
проверок интерфейс явно предупреждает, что это **не доказательство отсутствия
уязвимостей вне области применимых инструментов**.

## Проверки на приёмке

- Нулевой inventory: без деления на ноль, без фиктивных статусов.
- Отсутствующий `riskSummary`: «Статус не подтверждён», категория уточнения.
- Корректные свежие источники: соответствующая категория и значения риска.
- Устаревшие источники с ранее найденными критическими событиями: не
  включаются в распределение **текущих** находок, остаются в категории
  «Без свежего аудита» и доступны через исходную историю.
- Неполный свежий аудит: категория уточнения, текущие наблюдения сохраняются.
- Некорректные или переполненные счётчики: уточнение, без выдуманной полноты
  и без завышения сумм.
- Все фильтры: отсутствие пересечения, сумма категорий равна числу хостов,
  таблица показывает только выбранную категорию.
- Дата последнего аудита берётся только из подтверждённого
  `lastSecurityAuditAt`, а не из более нового сбора диагностических фактов.
