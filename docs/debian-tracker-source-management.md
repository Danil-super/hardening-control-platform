# Debian Security Tracker — управление источником через HCP (Issue #12)

Новая секция **«Источники → Debian Security Tracker»** работает только на управляющем сервере HCP. На целевых хостах ничего запускать или настраивать не требуется.

## Обычный сценарий

1. Войдите в панель администратора, откройте «Источники». Для сетевой загрузки выберите сетевой режим базы.
2. Нажмите «Загрузить с Debian». Контроллер скачивает JSON только с фиксированного `https://security-tracker.debian.org/tracker/data/json` (без произвольных URL, cookie, редиректов и фонового обновления), проверяет ограничение размера декодированного ответа, JSON, дубли ключей и структуру, сохраняет неизменяемый снимок.
3. Проверьте отображаемые дату локального получения, количество записей и SHA-256. Нажмите отдельно «Выбрать снимок для CVE-сверки». Перед активацией контроллер **заново проверяет полные байты** и срок локального импорта. Выбор сохраняется в SQLite и применяется к новым отчётам Debian.
4. При необходимости нажмите «Отключить сверку Debian». Это не удаляет снимки и не меняет обычный Trivy-аудит.

Действующий снимок **не изменяется от скачивания**. После перезапуска Docker выбранная контрольная сумма сохраняется в `runtime_settings`. Состояние защищено существующей авторизацией панели (`/api/settings/:path*`) и проверкой Origin для POST/PATCH. Изменения и импорт записываются в журнал HCP без содержимого всей базы.

`HCP_DEBIAN_TRACKER_PREVIEW_SHA256` остаётся начальным fallback-параметром до первого выбора в интерфейсе. Явное выключение в интерфейсе имеет приоритет над `.env`. Параметр `HCP_DEBIAN_TRACKER_MAX_IMPORT_AGE_HOURS` (по умолчанию 168, допустимо 1–8760) ограничивает срок **локального снимка**, а не дату публикации издателя. Новая загрузка того же точного JSON не обновляет исходное `capturedAt`, поэтому не может искусственно сделать старые данные актуальными.

В offline-режиме базы CVE сетевой импорт блокируется; ранее утверждённый снимок доступен локально. Одновременно допускается только один импорт на процесс контроллера. На нескольких процессах публикация неизменяемых файлов остаётся атомарной, но для полного межпроцессного управления заданиями требуется отдельный журнал/lock.

## Границы доверия

`observed-at-capture` означает лишь фактически загруженные байты и SHA-256. Ни TLS, ни совпадение хеша не удостоверяют подпись Debian, свежесть издателя или полноту CVE. Импорт **не** обновляет Trivy-базу; Debian Tracker даёт отдельную предварительную оценку исходных пакетов, только для Debian. При расхождениях вывод Trivy сохраняется, а исправления по результату сверки не разрешаются.

API: `GET /api/settings/debian-tracker` — локальный статус без чтения всей базы; `POST` — явный импорт; `PATCH` — выбор только последнего импортированного и проверенного SHA либо отключение с optimistic CAS (`expectedSha256`). Произвольные пути и URL в запросе отклоняются. Прямой доступ к маршруту без администраторской сессии или доверенного Origin блокирует общий HCP proxy.

## Тесты и ограничения

`web/tests/debian-tracker-management.test.mjs` моделирует реальный JSON/HTTP без доступа в интернет и проверяет неизменность импортов, раздельность загрузки и выбора, CAS, порчу базы, устаревание, offline и конкуренцию. Нативные CI-сценарии регрессионно проверяют сканеры и восстановление firewall.

Загрузка полной базы может потребовать существенной оперативной памяти (до установленного лимита 128 МиБ **декодированного** HTTP тела плюс JSON-структуры). Этот режим предназначен для Docker/control-node, не для короткоживущей serverless-функции. Криптографическая аттестация производителя, проверка подписанного происхождения установленных пакетов и автоматическое изменение пакетов остаются за пределами реализованного сценария.
