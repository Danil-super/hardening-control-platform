# Подлинная Astra Linux 1.7.6.15 из официального OVA — отдельный нативный эксперимент

**Это исследовательская SSH-проверка, а не приёмка 18 правил, CVE или всей платформы.**

## Зачем нужен второй способ

Официальные Astra 1.7.6.UU2 **cloud-init** образы MG15.3.1 и MG15.1.0
подтвердили версию гостевой Astra, но не завершили штатный модуль
`scripts_per_once`, поэтому дальнейшие сканеры не выполнялись.
Нельзя отключать этот модуль в прежних экспериментах и объявлять PASS.

Здесь исследуется **другой официальный образ**, предназначенный для
VirtualBox, а не для cloud-init. Никакие системные защитные механизмы
Astra не отключаются. Запуск происходит в одноразовой изолированной
GitHub-hosted QEMU/KVM машине; пользовательская Astra не затрагивается.

## Проверенный исходный файл

Оригинальный Astra Linux UBI каталог:
https://registry.astralinux.ru/ui/native/mg-generic/alse/virtualbox/

Имя: `alse-1.7.6.uu2-base-virtualbox-mg15.3.1-amd64.ova`.

Официальный Artifactory Storage API, дата сверки **05.11.2026**:
- Размер: **427995648 байт**
- SHA-256: `72ccb335f4c46b5b6d1410cfe0c08f648f95a5e6fd1026f6e0b2d65d8b7ebf6e`

Источник: https://registry.astralinux.ru/artifactory/api/storage/mg-generic/alse/virtualbox/alse-1.7.6.uu2-base-virtualbox-mg15.3.1-amd64.ova

**Ограничение доверия:** SHA и файл получены с одного сайта изготовителя.
Это контроль неизменности байтов относительно закреплённого снимка,
но не независимо подтверждённая цифровая подпись производителя.

## Что проверяет CI

Workflow: `.github/workflows/astra17-ova-kvm.yml`.

1. Только GitHub-hosted runner, свой каталог внутри `RUNNER_TEMP`.
2. Загрузка оригинального OVA по строго заданному HTTPS URL без перенаправлений,
   проверка sidecar checksum и **отдельного точного SHA/размера в коде**.
3. Безопасное потоковое извлечение **ровно одного обычного VMDK** из
   OVA. Запрещены symlink, traversal, спецфайлы и несколько дисков.
   Тесты не применяют небезопасный `tar.extractall`.
4. Конвертация VMDK в собственный QCOW2 и создание одноразового overlay;
   исходный файл не меняется.
5. Запуск новой QEMU VM с SSH, доступным только через loopback runner.
   Для первого тестового входа применяется **публично документированный
   заводской пароль** только своего оригинального одноразового образа.
   Он хранится во временном приватном файле, никогда не попадает в argv,
   журнал GitHub или артефакт. Этот пароль **недопустим в рабочей установке**.
6. После первого подключения фиксируется SSH host key в отдельном
   `known_hosts`; дальнейшие соединения требуют точно его же.
   Первоначальная привязка — только к своей временной QEMU VM, **не**
   независимое доказательство доверия к удалённому хосту.
7. Через реальный SSH считываются фактические файлы:
   `/etc/os-release`, `/etc/astra_version`,
   `/etc/astra/build_version`, ядро, архитектура и machine-id.
   Исходный machine-id, приватные диски, ключи и журналы **не публикуются**.
   Требуются `ID=astra`, `1.7.6` и полная сборка `1.7.6.15`.
8. Повторное новое SSH-подключение должно подтвердить прежнюю идентичность.

Публикуется только безопасный JSON-протокол, включая категории проверок
и SHA-256 приватного наблюдения, без исходных секретов.

## Не выдавать узкую проверку за полную

Даже при успешной первой проверке JSON всегда содержит:

- `fullNative18RuleAcceptance=false`;
- `ovalEvaluationPerformed=false`;
- `hardenedProdReady=false`;
- `publisherSignatureIndependentlyVerified=false`.

Это только проверка реального запуска и SSH-идентичности Astra **base**.
После PASS нужно отдельно добавить штатные HCP Ansible facts, OpenSCAP,
18-rule baseline → контролируемое изменение → откат, полный vendor OVAL,
публикацию evidence через production normalizer и операторскую приёмку
на собственной Ubuntu. Усиленный и максимальный режимы независимы.

При ошибке image/OVA/SSH фиксировать честный отрицательный результат.
Не подменять реальный вывод фикстурами; не запускать сценарий на пользовательских хостах.
Issues #40/#38/#43 остаются **открытыми**.
