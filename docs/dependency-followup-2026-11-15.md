## Удаление лишнего пакета коллекций Ansible

В Dockerfile `ansible` заменён на `ansible-core`. Полный пакет содержит
неиспользуемые коллекции, в том числе `ansible.posix.authorized_key`, к которому
относится исходная запись CVE-2026-11837. Штатные playbook HCP используют
`ansible.builtin`; собственная установка ключа HCP этот модуль не вызывает.
Контракт пользовательских сценариев уточнён в [инструкции](../deployment/README.md).
Совместимый старый core и отдельный современный runtime сохраняются;
EOL старого core этим не устраняется.

В container CI добавлена проверка отсутствия пакета коллекций и syntax-check
всех 14 штатных playbook. Проверка сначала отклонила прежний образ, затем
прошла в отдельной копии после удаления только `ansible`.
Для этой копии отдельно прошли:

- 373 Ansible/Python и 240 deployment-тестов, без пропусков;
- настоящий локальный модуль в старом и современном Ansible;
- четыре Python installer, vendor floors и `pip check`.
- Настоящий SSH к собственной цели во внутренней Docker-сети: старый и
  современный runtime выполнили `collect-facts` и `package-inventory`.
  Все 139 записей пакетов совпали между runtime; четыре отчёта сохранены.
  Цель, сеть и временные ключи удалены, порты хоста не публиковались.

Копия получена удалением пакета из прежнего образа, а не новой сборкой Dockerfile.
Это проверка совместимости. Рабочий HCP, Astra и их секреты не использовались.
Минимум MemAvailable при полном наборе — 7 859 355 648 байт; OOM/guard не сработали.
Целью SSH была одноразовая Debian-копия, не Astra; приёмку Astra это не заменяет.
Современный Ansible выдал прежнее предупреждение об изменении facts в 2.24;
текущие четыре запуска завершились без unreachable/failed.

Доступ к npm и GitHub API с управляющей машины сейчас останавливается на TLS/
connect timeout; DNS работает. Context7 не ответил, официальный сайт Ansible
также недоступен. Состав пакетов проверен по установленным метаданным Debian
и настоящим CLI, без предположений о новых API. До восстановления доступа
