# Предварительная проверка управляющей Ubuntu одной командой

Этот этап относится к [issue #43](https://github.com/Danil-super/hardening-control-platform/issues/43).
Проверка **только читает** локальную конфигурацию. Она не устанавливает
пакеты, не запускает и не останавливает контейнеры, не подключается по SSH,
не запускает сканеры и не изменяет целевые машины. **Успех не означает,
что HCP принят для production.**

## Первый запуск после настройки .env

На управляющей Ubuntu, находясь в каталоге репозитория:

```bash
python3 deployment/tests/preflight_control_node.py --project-dir . --env .env
```

Проверяются строгие права `.env`, независимые непустые секреты по уже
существующему `validate_production_env.py`, каталог `secrets` (0700),
`known_hosts` (0600), инвентарь, основные файлы и `docker compose
version --short` + `docker compose config --quiet`.

**Никакие секреты, аргументы/ошибки Docker Compose или значения инвентаря
не печатаются.** Выводятся только статусы, безопасные коды причин и
структурированные блокировки. Нет `sudo`; если у оператора нет доступа к
Docker, это фиксируется как ошибка и исправляется им вне скрипта.

После **отдельного** запуска контейнера в соответствии с README:

```bash
python3 deployment/tests/preflight_control_node.py --check-running
```

Дополнительно читается `docker compose ps --format json`, проверяются только
`Service=hcp`, `State=running` и `Health=healthy`. Другие поля
контейнера и stdout/stderr не публикуются. Эта проверка НЕ выполняет
HTTP-логин и не удостоверяет авторизацию/403/401, HMAC, backup, SSH или откат.

Для локальных офлайн-проверок без установленного Docker:

```bash
python3 deployment/tests/preflight_control_node.py --without-docker
```

Коды возврата: **0** — локальная конфигурация прошла выбранные проверки,
**1** — есть блокирующее нарушение или недоступная проверка. Поле
`operatorAcceptanceCompleted=false` всегда остаётся ложным.

Для защищённой локальной квитанции можно добавить
`--output /private/isolated/new-readiness-receipt.json`. Файл создаётся
только впервые, с правами 0600 вне рабочего каталога; существующий
не перезаписывается.

Реальный цикл из issue #43: независимый тестовый control node,
авторизация 401/403, настоящий мастер SSH, сохранение исходных отчётов,
остановленный backup, перенос на вторую Ubuntu, HMAC и отзыв старых сеансов,
новая SSH-проверка и безопасный rollback firewall на изолированной цели.
Без внешнего контроля и подписи оператора **issue #43 остаётся открытым**.
Нативная Astra 1.7.6.15 (#40) проверяется отдельно.

Unit-тесты: `deployment/tests/test_preflight_control_node.py`.
