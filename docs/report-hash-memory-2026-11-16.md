# Память при хешировании исходных отчётов

Следующий срез [плана аудита](../tasks/plan.md): устранена полная копия
JSON, которую `hashAnsibleReport` создавал только для SHA-256. Функция
используется при добавлении находок в план, проверке доказательств и
создании/повторной проверке манифеста итогового PDF.

Теперь один открытый файл читается блоками 1 МиБ по существующему шаблону
проверки OVAL. Дескриптор закрывается в `finally`, ошибки по-прежнему
возвращают null. Синхронный интерфейс, проверка ID/пути, точные исходные
байты, формат SHA-256 и все вызывающие функции сохранены. Новых
зависимостей, настроек, кэшей или изменений БД нет.

## Воспроизведение и измерение

На прежнем коде тест файла 64 МиБ дал лишние 50 425 856 байт пикового RSS
и упал при пороге 32 МиБ. После исправления проверены точный digest,
пустой файл, границы блоков, последний неполный блок, UTF-8, недопустимый
ID, отсутствующий файл и отсутствие утечки дескрипторов при ошибке чтения.
Все 37 целевых тестов, включая план работ и итоговые PDF, прошли.
Полный набор: 646 web-тестов без пропусков, typecheck, production build и
144 HTTP-проверки. Минимум MemAvailable — 4 570 161 152 байта; OOM и
защитной остановки не было. Рабочие отчёты и настройки Astra не менялись.

Одинаковые образ `c3bc2e15`, CPU=1, memory=memory+swap=2 ГиБ, без сети;
свежий Node-процесс на каждый замер. Файл 268 435 519 байт:
SHA-256 `6aa6154081da0161c486ea93fc53876deff8283f15a78f9dd3ed39a527078980`.
Digest независимо сверен Python и совпал во всех четырёх измерениях.

| Код | Пик RSS процесса, два замера | Время хеширования |
| --- | --- | --- |
| Прежний `2d49599` | 323 072 000 / 323 014 656 байт | 222,9 / 211,7 мс |
| Чтение блоками | 71 000 064 / 71 008 256 байт | 147,7 / 146,3 мс |

В этом сценарии пик ниже примерно на 78%; это RSS отдельного процесса,
не всей панели/компьютера и не SLA. Тест не подменяет разбор JSON: чтение
подробного отчёта и его нормализация остаются отдельной нагрузкой.

Graphify обновлён для HCP, Code Graph CLI использовал тот же абсолютный
корень. Найденные им прежние Markdown anchors не изменялись; интерфейс
экспортируемой функции проверен по всем трём вызывающим модулям.
Приватные команды, RED/GREEN, замеры и журналы:
`~/.local/state/hcp-evidence/report-hash-20261116-u80fmv0_/`.

Пока это локальный кандидат. Рабочая панель остаётся на `f3aaeae` /
`c3bc2e15`; полный Dockerfile, CI нового SHA и установка этого исправления
ещё не подтверждены. Общий бюджет OVAL/Trivy/разбора JSON, прежние CVE/EOL
и независимое хранение резервной копии остаются открытыми.
