# Нативная сквозная проверка CVE Debian: инвентарь → Trivy → Tracker → JSON/PDF

Рабочая область: **Debian 12/bookworm**, одноразовый KVM-гость на GitHub-hosted runner, действительный Trivy, текущая общедоступная выгрузка Debian Security Tracker, финальный отчёт HCP. Данная процедура **не устанавливает уязвимые пакеты на гостевую ОС** и не создаёт автоматических исправлений.

## Две независимые части одного испытания

**А. Фактически установленный пакет.** Сначала штатный `package-inventory.yml` собирает инвентарь с гостя по SSH. Платформа сверяет все восемь native-полей каждого пакета с независимым `dpkg-query` внутри принадлежащего тесту гостя: статус установки, бинарный пакет/версия, архитектура, исходный пакет/версия, Maintainer и Origin. Отдельный пост-VM тест берёт **только наблюдённые** версии исходного пакета `openssl` и сравнивает их с одной неизменяемой полной выгрузкой Debian Security Tracker для `CVE-2024-6119/bookworm`. Не создаётся ложное срабатывание Trivy для установленного гостя; отсутствие CVE в Trivy не превращается в обещание защищённости.

**Б. Маркированный контроль.** Для проверки **полного рабочего пути HCP** используется отдельно размеченный JSON-инвентарь `control-vulnerable` с исходной версией `openssl 3.0.14-1~deb12u1`. Это **синтетические метаданные**, на госте такая версия не устанавливается. В сценарии используется действительная production-функция `scanPackageInventory` и Trivy 0.74.0, работающий с неизменённой базой предыдущего нативного прогона в offline-режиме. После явного выбора уже проверенного SHA-256 снимка Debian HCP сохраняет предварительный `debianTrackerPreview` с отдельными `trustedVerdict=unknown` и `remediationAuthorized=false`.

Контроль проходит штатный `readAnsibleReport`, далее `createProjectReport`. Сохранённый JSON включает каждую исходную пару CVE×пакет×версия с полным и производным SHA-256; модуль `assertDebianTrackerEvidenceMultiset` независимо сравнивает множества с учётом кратности и исходных идентификаторов. **Реальный PDF** проверяется чтением сжатых потоков страниц: все ID находок, обе контрольные суммы и хеш проекции должны присутствовать в отрисованном документе.

## CI

- Одноразовый VM workflow: `.github/workflows/linux-deb-vm-integration.yml`. Для Debian добавлен пост-VM этап `verify_debian_tracker_native_report.mjs`, выполняемый **после остановки гостя**, без SSH и без команд на целевом хосте.
- Реальный Debian Security Tracker извлекается только с закреплённого официального HTTPS-адреса, с теми же ограничениями размера (128 МиБ распакованных данных), структуры и редиректов, что в production. Файл базы остаётся во временном защищённом каталоге и **не загружается в артефакты**.
- Дополнительный протокол `artifacts/debian-vendor-native/protocol.json` содержит только публичные результаты и SHA-256, без machine-id, ключей SSH или содержимого полной базы. Публикация разрешается только при двух успешных протоколах — нативном и CVE/финальном PDF.
- `verify_debian_tracker_native_report.test.mjs` отвергает поддельный OS ID, отсутствие подтверждения всех native-полей, неполный инвентарь, и маркированный контроль, который неправомерно объявлен установленным на госте.

## Ограничения

Тест доказывает согласованность данных в указанном выпуске и отдельных контрольных CVE, но **не** универсальное покрытие уязвимостей всех Debian-пакетов. Поля Maintainer/Origin в dpkg сохраняются как наблюдения, а не криптографическая аттестация установленного пакета. HTTPS/SHA-256 полной базы не являются цифровой подписью издателя Debian. Результат не подтверждает актуальность всех бюллетеней и не даёт прав на автоматическое исправление пакетов.

Путь к тестовому инвентарю, накопителю исходного полного JSON и виртуальному диску остаётся приватным. На продуктивных целевых хостах указанная лаборатория не запускается.
