# Ограничение установки пакетов в одноразовой Astra CI

14 ноября workflow на документационном коммите `613a3d0` остановился
на `native_openscap_install_on_disposable_vm`: SSH-команда установки OpenSCAP
не завершилась за 900 секунд. До проверки исходных 18 правил и полного OVAL
запуск не дошёл. Установленный сайт `ff5597d` не менялся; его собственный
проверенный SHA ранее прошёл все 20 workflow и 28 checks.

Причина задержки самой установки по этому исключению не установлена.
Исправлен проверяемый недостаток управления процессом: таймаут локального
SSH не задавал отдельного срока APT внутри гостя, а код его завершения терялся.

Все четыре APT-вызова подготовки OpenSCAP/schema в этом native-тесте теперь
используют общий CI-only участок:

- Внутренний GNU `timeout`: 840 секунд, TERM, затем KILL через 10 секунд;
  отдельная process group, без `--foreground`. Внешний SSH остаётся 900 секунд.
- `Acquire::Retries=2` и таймаут бездействия HTTP/HTTPS 35 секунд применяются
  к update и install. Это не глобальный срок скачивания: его задаёт `timeout`.
- `DEBIAN_FRONTEND=noninteractive`, закрытый stdin и `sudo -n`.
- В протоколе остаются операция и числовой `exitCode`; при обрыве транспорта
  код неизвестен (`null`). 124 означает timeout, 137 — KILL без выдуманной
  причины сигнала; остальные ошибки установки остаются отказом.
- Сырой вывод APT не публикуется. Коды ошибок пропускаются через существующий
  конечный allowlist публичного протокола; неизвестные исключения скрываются.

Только собственная одноразовая ВМ GitHub-hosted CI после закрепления SSH-ключа
и проверки исходной OVA. Проверки подписи пакетов, XML/XSD, точных определений
и `partial=false` не ослаблены. Производственные playbooks и Dockerfile
не затронуты, настройки пользовательской Astra не менялись.

## Локальная проверка

Новые тесты сначала упали, затем прошли. Один выполняет настоящий GNU timeout
с собственными заменами `sudo`/`apt-get`: зависший процесс и его ребёнок
завершаются, приватный контрольный stderr не выходит наружу. Дополнительные
кейсы проверяют запрет self-hosted, коды 0/100/124/137, отказ при неизвестном
ответе и сохранение разрешённого failureCode в настоящем public writer.
Удаление проверки exitCode в отрицательном контроле обнаружено тестами.

Все **240 deployment-тестов** прошли без пропусков в контейнере 512 МиБ,
без сети и рабочих секретов. Graphify обновлён, Code Graph review выполнен;
его предупреждения о вызовах `apt`/`sudo` относятся к локальным переменным
`Path` в тестовом fixture, а не к функциям с изменённой сигнатурой.
Реальный повтор нового native CI должен проверяться отдельно по новому SHA.

Материалы: `~/.local/state/hcp-evidence/native-apt-20261114/`.
Сохранён исходный отказ. Доступность стороннего репозитория этим изменением
не гарантируется; неисправная установка не выдаётся за выполненный аудит.

Документация: [GNU timeout](https://www.gnu.org/software/coreutils/manual/html_node/timeout-invocation.html),
[APT configuration](https://manpages.debian.org/bookworm/apt/apt.conf.5.en.html).
