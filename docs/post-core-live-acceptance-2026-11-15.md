# Повторная приёмка установленного HCP на рабочей Astra

15 ноября после запуска ВМ проверена установленная версия `97b4bef`, образ
`3a6d15a442f452bec1015d60dc286781ffd3bc124b17536f4b7302625c8d18a4`.
Проверки запускались штатным API заданий HCP последовательно на прежнем
закреплённом активе. Перед ними подтверждены SSH-идентичность, sudo и
отсутствие активных заданий. Пароль использован только в памяти.

| Проверка | Результат | Время |
| --- | --- | ---: |
| Сведения о хосте — Ansible | Завершена, partial=false; kernel/архитектура отражены в PDF | 4,2 с |
| Профиль конфигурации — OpenSCAP | Все 18 правил pass, partial=false | 28,3 с |
| Временный Lynis | Индекс 71; 4 warning и 49 suggestion, partial=false | 86,5 с |

Индекс Lynis не является процентом защищённости. Успех выбранных 18 правил
не доказывает отсутствие всех уязвимостей. Системные настройки Astra не
применялись; временный каталог Lynis после завершения независимо проверен
через закреплённый SSH. Для этого чтения sudo не использовался.

## Исходники и PDF

- У OpenSCAP скачаны ARF (68 120 байт), исходный профиль (39 215 байт) и
  нативный HTML. Размеры/hash совпали с сохранёнными оригиналами; все 18
  ID и состояний ARF совпали с HCP, все ID присутствуют в HTML и PDF.
- У Lynis скачан настоящий `report.dat` (151 995 байт), проверены размер/hash,
  `finish=true`, индекс 71 и полное мультимножество исходных warning/suggestion.
  Все 53 наблюдения представлены в HCP и PDF, без потери повторяющихся записей.
- PDF всех трёх запусков имеют верный source SHA-256; сведения о хосте также
  проверены по фактическим полям. Отдельный оригинал сканера для facts не
  придумывался: playbook сохраняет выбранные сведения в JSON HCP.

Сохранённые отчёты:

- `host-172.16.95.128-facts-run-20261115T145353885Z-14fa04d1`;
- `host-172.16.95.128-openscap-run-20261115T145358430Z-12e9b8cd`;
- `host-172.16.95.128-lynis-run-20261115T145427182Z-b9f5c681`.

Все прежние 152 файла сохранили байты; стало 158 файлов, 53 активных и
41 архивный отчёт. HMAC-цепочка валидна: 314 записей с защитой payload.
Минимум MemAvailable во время аудитов/выгрузок — 5 037 015 040 байт
(около 4,69 ГиБ). Порог 2,25 ГиБ не сработал. Это измерение одного
последовательного прогона; системный swap использовался.

## Свежая холодная копия после аудитов

После завершения заданий и выгрузок создан новый согласованный снимок
остановленного контроллера, не переупаковка прежних данных. Панель была
приостановлена на 64,794 с, затем стала healthy; все 13 прикладных таблиц
и 158 файлов совпали до/после. ВМ не выключалась. SQLite checkpoint,
архивация и gzip выполнялись отдельными контейнерами с лимитом 256 МиБ / 1 CPU.

Manifest pin:
`a8847ac24a510fb4d33c731fbbd53f2ece030b04ff989a6124c6f344270ff499`.
Размеры архивов: runtime 597 028 221, настройки 5 285, образ 967 453 205 байт.

Именно этот комплект полностью восстановлен в отдельной внутренней сети
на том же сохранённом образе. Pin проверен до SQLite/HMAC-ключа; проверены
байты, HMAC 314, 53/41 отчётов, login/CSRF, отзыв ранее валидной сессии,
готовая OVAL-база и cache/no-op. Для сохранённых OpenSCAP/OVAL заново
скачаны XML/PDF: подтверждены все 18 и 4 161 ID соответственно. Это проверка
восстановленных отчётов, а не новый полный OVAL-аудит рабочей Astra.

Восстановление заняло 184,7 с. Минимум MemAvailable — 4 092 067 840 байт,
свободного диска — 5 909 475 328 байт; OOM/защитные пороги не сработали.
Доступ стенда к рабочей Astra запрещён и проверен. Контейнер, сеть и
распакованный runtime/settings после проверки удалены; рабочие данные целы.

Закрытые материалы и комплект:
`~/.local/state/hcp-evidence/post-core-live-20261115-_ywkh225/delivery-kit/`.
Протоколы лежат в родительском каталоге. Старые архивы сохранены.
Секреты/приватные ключи входят в комплект; в Git он не добавляется.
Хранение остаётся локальным, hardlink и pin на этом же диске не являются
независимой внешней копией или самостоятельным подтверждением происхождения.

## Границы этапа

Новый полный OVAL и изменения/rollback firewall на рабочей Astra в этом
этапе не запускались. Остаточные CVE, EOL Ansible, независимый DR/anchors,
универсальный бюджет памяти и три полных OVAL одновременно не закрыты.
Исправления [транспортной устойчивости CI](native-download-retry-2026-11-15.md)
относятся к отдельным коммитам; рабочий образ в этом этапе не менялся.
