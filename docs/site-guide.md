# Краткая инструкция по работе с сайтом

1. Откройте сайт и убедитесь, что в левом меню указан демо-режим. В этом режиме платформа не меняет реальную операционную систему.
2. Перейдите в раздел `Профили` и выберите подходящий профиль аудита: базовое усиление Linux, безопасность SSH, усиление веб-сервера или усиление Docker-хоста.
3. Нажмите `Запустить аудит`. Сайт покажет этапы демо-проверки и перенаправит на страницу результатов.
4. На странице результатов изучите оценку защищенности, количество рисков и таблицу найденных проблем. Используйте фильтры по риску и категории.
5. Нажмите `Сформировать план исправлений`, чтобы открыть планировщик исправлений.
6. В планировщике выберите нужные действия. Для каждого действия показаны риск, затрагиваемые файлы, необходимость резервной копии, доступность отката и шаги выполнения.
7. Нажмите `Сформировать демо-отчет`. Сайт имитирует создание резервной копии, проверку и повторный аудит без изменения ОС.
8. Перейдите в раздел `Отчеты`, чтобы увидеть сравнение “до/после”, список исправленных и оставшихся проблем, ручные рекомендации и записи резервных копий.
9. При необходимости нажмите `Экспорт JSON` или `Экспорт HTML`, чтобы скачать отчет.
10. Раздел `Локальный Linux-агент` показывает, как веб-платформа взаимодействует с реальными audit-only проверками хоста.

## Главный компьютер с Ansible

Этот сценарий нужен для работы с несколькими устройствами в локальной сети. Сайт и Ansible запускаются на одном главном компьютере, а остальные Linux-хосты доступны по SSH.

1. Установите Ansible на главном компьютере:

```bash
sudo apt install ansible openssh-client python3
```

2. Создайте inventory:

```bash
cp ansible/inventory.example.ini ansible/inventory.ini
```

3. Укажите IP-адреса и SSH-пользователей в `ansible/inventory.ini`.
4. Проверьте доступ:

```bash
ansible all -i ansible/inventory.ini -m ping
```

5. Запустите сайт локально:

```bash
cd web
npm run dev:lan
```

6. Откройте `/hosts`.
7. Нажмите `Проверить control node`.
8. В блоке автообнаружения проверьте подсеть, SSH-пользователя и нажмите `Сканировать и добавить`.
9. Найденные хосты с открытым SSH-портом 22 будут добавлены в `ansible/inventory.ini`.
10. При необходимости нажмите `Установить audit-only агент`.
11. Запустите `Audit-only` или расширенный аудит с Lynis/OpenSCAP.
12. JSON-отчеты будут сохранены на главном компьютере в `ansible/reports/`.

## Импорт результата реального агента

Этот сценарий выполняет аудит без исправления: агент читает настройки, запускает проверки и возвращает JSON. Команды `remediate` и `rollback` в текущей версии не применяют изменения ОС.

1. Перейдите в папку `agent`.
2. Для ручного audit-only отчета выполните:

```bash
sudo python3 agent.py audit --profile basic_linux --pretty > ~/Загрузки/agent-report.json
```

3. Для расширенного audit-only отчета с внешними сканерами выполните:

```bash
sudo python3 agent.py audit --profile basic_linux --include-lynis --include-openscap --pretty > ~/Загрузки/agent-report.json
```

4. Для автоматического импорта через сайт запустите локальный промежуточный сервер:

```bash
python3 server.py
```

5. Для установки как systemd-сервис сначала проверьте план:

```bash
./install.sh --dry-run
```

6. Затем при необходимости установите и запустите сервис:

```bash
sudo ./install.sh --enable --start
```

7. Проверьте агент:

```bash
./doctor.sh
curl http://127.0.0.1:8765/health
```

8. На сайте откройте `/agent/import`.
9. Нажмите `Проверить bridge`, чтобы убедиться, что локальный сервер доступен.
10. Выберите профиль и нажмите `Получить аудит от агента`. Для расширенной проверки включите переключатели `Включить расширенный аудит Lynis` и/или `Включить аудит OpenSCAP / SCAP Security Guide`.
11. Каждый успешный импорт сохраняется в истории браузера.
12. Чтобы сравнить два результата, выберите базовый и текущий отчет в блоке `Сравнение отчетов`.
13. Если автоматический запрос недоступен, выполните:

```bash
python3 agent.py audit --profile basic_linux --pretty > agent-report.json
```

14. Загрузите файл `agent-report.json` на странице `/agent/import`.
15. Для удаления сервиса используйте:

```bash
sudo ./uninstall.sh --dry-run
sudo ./uninstall.sh --remove-files
```

## Демо-хост / источник аудита

В MVP аудит выполняется на демонстрационном хосте `demo-ubuntu-24.04.local`. Источник данных — локальный демонстрационный движок.
Это значит, что сайт показывает реальный пользовательский сценарий платформы, но не выполняет системные команды и не меняет ОС.

Такой режим нужен для безопасной демонстрации на Vercel. Реальный аудит уже можно показать отдельно через локальный Python-агент и страницу `/agent/import`.
