# Инструкция по работе с платформой

Панель управляет реальными Linux-хостами в локальной сети. Перед началом проверьте SSH fingerprint, отдельного технического пользователя и sudo-права, нужные только для согласованных задач.

1. Откройте `/hosts`, проверьте control node и добавьте хост: alias, IP/hostname, SSH user, port, group и sudo.
2. Сначала используйте «Проверить»: платформа выполняет SSH, Python и sudo preflight без записи в inventory.
3. Сохраните хост и выберите профиль: `Linux`, `SSH`, `Web` или `Docker`.
4. Запустите аудит. Отчет с доказательствами сохраняется локально; историю хоста можно открыть из таблицы.
5. Для инвентаря пакетов и Trivy используйте «Проверить пакеты и CVE». **Для CVE Astra** назначьте группе базу в «Источниках» → «CVE пакетов Astra» и отдельно запустите «Проверить CVE Astra по OVAL». Для конфигурационного OpenSCAP назначьте в «Политиках» профиль «Astra Linux — базовые проверки HCP», затем запустите «Проверить профиль OpenSCAP». [Порядок подготовки](astra-audit.md).
6. Для нескольких источников откройте «Сводка» в отчётах: она показывает совпадения CVE, портов и scanner-правил, не складывая оценки риска.
7. Перед изменением изучите отчет. В блоке «Обратимые изменения» укажите параметры и понятную причину.
8. Нажмите «План», введите alias выбранного хоста и изучите результат `--check --diff`. Конфигурация firewall не изменяется; временный helper передаётся и удаляется даже для предварительной проверки.
9. Нажмите «Применить», снова введите alias. Платформа сохранит backup UFW/firewalld на хосте, выполнит действие и запустит повторный аудит.
10. Если изменение требуется отменить, найдите транзакцию со статусом `applied`, `failed` или `rollback_failed` **с сохранённой резервной копией**, нажмите «Откатить» и подтвердите alias. После отката запустите аудит вручную, чтобы получить отчет нового состояния. При нескольких изменениях одного хоста откатывайте их в обратном порядке.

Автоматический backup содержит только конфигурацию активного UFW/firewalld и остаётся в `/var/lib/hcp-backups` на целевой машине. HCP не делает снимок всей ОС и не создаёт автоматически резервную копию собственной SQLite. Команды для данных платформы: [бэкап и восстановление](backup-restore.md). При потере SSH для восстановления может потребоваться консоль ВМ; автоматического отката по таймеру нет.

## Регулярный аудит

Не используйте API-планировщик веб-приложения: периодический аудит запускается systemd timer на control node. Установка описана в `deployment/README.md`. Timer вызывает отдельную команду в контейнере и использует `flock`, поэтому перезапуск панели не отменяет расписание и не создает параллельные проверки.

Задача `packages` означает инвентарь и Trivy. Отдельный OVAL-аудит Astra в штатное расписание пока не включён; запускайте его вручную в «Хостах». OpenSCAP включается отдельно после назначения профиля.

## Допустимые действия

В текущей версии через панель разрешены только обратимые операции firewall:

- закрытие конкретного TCP/UDP-порта; TCP 22 и фактический SSH-порт управления защищены;
- блокировка IPv4-адреса с проверкой адреса управляемого хоста, фактического источника SSH и дополнительных адресов `HCP_CONTROL_IPS`.

Создание пользовательских YAML-аудитов отключено по умолчанию. Его можно включить лишь для development-контура переменной `HCP_ENABLE_CUSTOM_AUDITS=true`; такие audit-playbook'и не должны выполнять изменения.
