# Инструкция по работе с платформой

Панель подключает Linux-хосты с помощью одноразового SSH-пароля и устанавливает отдельный ключ для каждой машины. Установка, ключи, sudo и добавление машины описаны в **[единой инструкции Ubuntu → Astra](ubuntu-astra-setup.md#host-onboarding)**. Эта страница продолжает её после настройки подключения.

1. Просканируйте сеть или укажите адрес. Введите логин и пароль администратора Astra, нажмите «Подключить хост». Если форма запросит подтверждение сервера, вставьте отпечаток из доверенной консоли этой Astra или реестра и нажмите «Сверить и сохранить», затем снова «Подключить хост». HCP сравнивает ключ целевой Astra по сети, а не собственный ключ Ubuntu. Вход, создание отдельной пары, проверка прав root и сохранение выполняются автоматически. Пароль вводится через HTTPS/localhost и не сохраняется.
2. Для уже добавленного хоста используйте «Настроить». Укажите административную учётную запись и нажмите «Сохранить подключение». При смене пользователя или переходе со старого общего ключа введите пароль для установки индивидуального ключа. История сохраняется.
3. Выберите хост и профиль: «Базовый Linux», «SSH-сервер», «Веб-сервер» или «Docker-хост». В блоке «Основной аудит» нажмите «Проверить профиль» и откройте отчёт; проверьте полноту и ошибки сбора. «Проверить связь» — только быстрая проверка SSH/Ansible.
4. Для административного режима используйте root с разрешённым SSH-входом либо администратора, у которого работает `sudo su`. При первом подключении HCP проверяет sudo разовым паролем, не меняет `sudoers` и не хранит пароль. Для каждого ручного аудита, изменения и отката такого хоста введите пароль в поле «Пароль sudo для одного действия». [Требования к доступу](ubuntu-astra-setup.md#sudo-access).
5. В «Источниках» для Trivy выберите «Сетевая база» и нажмите «Сохранить и загрузить» (либо «Загрузить общую базу CVE», если режим уже активен). Дождитесь статуса «актуальна»; далее кнопка «Обновить общую базу CVE» загружает новый снимок перед аудитом. Это одна общая база для поддерживаемых ОС. Затем в «Дополнительных проверках» выберите «Пакеты и CVE — Trivy». Для CVE Astra назначьте группе базу нужного выпуска в «Источниках» → «CVE пакетов Astra» и там же выберите «CVE Astra — OVAL / OpenSCAP». Для конфигурационного OpenSCAP назначьте в «Политиках» профиль «Astra Linux — базовые проверки HCP», затем выберите «Профиль конфигурации — OpenSCAP». [Подготовка сканеров](astra-audit.md).
6. Для нескольких источников откройте «Сводка» в отчётах: она показывает совпадения CVE, портов и scanner-правил, не складывая оценки риска.
7. В «Истории» хоста можно удалить отдельный ненужный тестовый отчёт. Связанный SBOM удаляется только если больше нигде не используется. Отчёты, уже включённые в план устранения, операцию изменения, итоговый PDF или последующую цепочку проверки, защищены от удаления; журнал действий и итоговые PDF не очищаются этой кнопкой.
8. Перед изменением изучите отчёт. В блоке «Обратимые изменения firewall» укажите параметры, причину и точное имя выбранного хоста в поле подтверждения.
9. Нажмите «Проверить план» и изучите результат. Конфигурация firewall не изменяется; временный helper передаётся и удаляется даже для предварительной проверки.
10. Нажмите «Применить». Платформа сохранит backup UFW/firewalld на хосте, выполнит действие и запустит повторный аудит.
11. Для отмены найдите транзакцию со статусом `applied`, `failed` или `rollback_failed` с сохранённой резервной копией, нажмите «Откатить» и подтвердите имя хоста. После отката запустите аудит вручную. При нескольких изменениях одного хоста откатывайте их в обратном порядке.

Автоматический backup содержит только конфигурацию активного UFW/firewalld и остаётся в `/var/lib/hcp-backups` на целевой машине. HCP не делает снимок всей ОС и не создаёт автоматически резервную копию собственной SQLite. Команды для данных платформы: [бэкап и восстановление](backup-restore.md). При потере SSH для восстановления может потребоваться консоль ВМ; автоматического отката по таймеру нет.

## Регулярный аудит

Не используйте API-планировщик веб-приложения: периодический аудит запускается systemd timer на control node. Установка описана в `deployment/README.md`. Timer вызывает отдельную команду в контейнере и использует `flock`, поэтому перезапуск панели не отменяет расписание и не создает параллельные проверки. Хост в режиме «sudo по паролю» намеренно не попадает в автоматический запуск: HCP не хранит его пароль. Для расписания используйте утверждённую техническую учётную запись или root по SSH.

Задача `packages` означает инвентарь и Trivy. Отдельный OVAL-аудит Astra в штатное расписание пока не включён; запускайте его вручную в «Хостах». OpenSCAP включается отдельно после назначения профиля.

## Допустимые действия

В текущей версии через панель разрешены только обратимые операции firewall:

- закрытие конкретного TCP/UDP-порта; TCP 22 и фактический SSH-порт управления защищены;
- блокировка IPv4-адреса с проверкой адреса управляемого хоста, фактического источника SSH и дополнительных адресов `HCP_CONTROL_IPS`.

Создание пользовательских YAML-аудитов отключено по умолчанию. Его можно включить лишь для development-контура переменной `HCP_ENABLE_CUSTOM_AUDITS=true`; такие audit-playbook'и не должны выполнять изменения.
