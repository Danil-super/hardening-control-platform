# Инструкция по работе с платформой

Панель подключает Linux-хосты с помощью одноразового SSH-пароля и устанавливает отдельный ключ для каждой машины. Установка, ключи, sudo и добавление машины описаны в **[единой инструкции Ubuntu → Astra](ubuntu-astra-setup.md#host-onboarding)**. Эта страница продолжает её после настройки подключения.

1. Просканируйте сеть или укажите адрес. Заполните пользователя и порт, подтвердите ключ сервера, введите SSH-пароль и нажмите «Создать ключ и настроить доступ». После автоматической проверки нажмите «Добавить хост». Пароль вводится через HTTPS/localhost и не сохраняется.
2. Для уже добавленного хоста используйте «Настроить». Здесь можно перевести старое подключение на индивидуальный ключ и явно настроить беспарольное sudo при наличии административных прав. Включите «Использовать sudo», повторите проверку и нажмите «Сохранить изменения». История сохраняется.
3. Выберите хост и профиль: «Базовый Linux», «SSH-сервер», «Веб-сервер» или «Docker-хост». Нажмите «Запустить аудит» и откройте отчёт; проверьте полноту и ошибки сбора.
4. Без sudo от обычного пользователя доступны только разрешённые ему данные; сетевые Nmap/SSH-проверки выполняются на управляющей машине. Защищённые данные и управление firewall требуют административных прав. [Режимы и настройка sudo](ubuntu-astra-setup.md#sudo-access).
5. Для инвентаря пакетов и Trivy используйте «Проверить пакеты и CVE». Для CVE Astra назначьте группе базу в «Источниках» → «CVE пакетов Astra» и отдельно запустите «Проверить CVE Astra по OVAL». Для конфигурационного OpenSCAP назначьте в «Политиках» профиль «Astra Linux — базовые проверки HCP», затем запустите «Проверить профиль OpenSCAP». [Подготовка сканеров](astra-audit.md).
6. Для нескольких источников откройте «Сводка» в отчётах: она показывает совпадения CVE, портов и scanner-правил, не складывая оценки риска.
7. Перед изменением изучите отчёт. В блоке «Обратимые изменения firewall» укажите параметры, причину и точное имя выбранного хоста в поле подтверждения.
8. Нажмите «Проверить план» и изучите результат. Конфигурация firewall не изменяется; временный helper передаётся и удаляется даже для предварительной проверки.
9. Нажмите «Применить». Платформа сохранит backup UFW/firewalld на хосте, выполнит действие и запустит повторный аудит.
10. Для отмены найдите транзакцию со статусом `applied`, `failed` или `rollback_failed` с сохранённой резервной копией, нажмите «Откатить» и подтвердите имя хоста. После отката запустите аудит вручную. При нескольких изменениях одного хоста откатывайте их в обратном порядке.

Автоматический backup содержит только конфигурацию активного UFW/firewalld и остаётся в `/var/lib/hcp-backups` на целевой машине. HCP не делает снимок всей ОС и не создаёт автоматически резервную копию собственной SQLite. Команды для данных платформы: [бэкап и восстановление](backup-restore.md). При потере SSH для восстановления может потребоваться консоль ВМ; автоматического отката по таймеру нет.

## Регулярный аудит

Не используйте API-планировщик веб-приложения: периодический аудит запускается systemd timer на control node. Установка описана в `deployment/README.md`. Timer вызывает отдельную команду в контейнере и использует `flock`, поэтому перезапуск панели не отменяет расписание и не создает параллельные проверки.

Задача `packages` означает инвентарь и Trivy. Отдельный OVAL-аудит Astra в штатное расписание пока не включён; запускайте его вручную в «Хостах». OpenSCAP включается отдельно после назначения профиля.

## Допустимые действия

В текущей версии через панель разрешены только обратимые операции firewall:

- закрытие конкретного TCP/UDP-порта; TCP 22 и фактический SSH-порт управления защищены;
- блокировка IPv4-адреса с проверкой адреса управляемого хоста, фактического источника SSH и дополнительных адресов `HCP_CONTROL_IPS`.

Создание пользовательских YAML-аудитов отключено по умолчанию. Его можно включить лишь для development-контура переменной `HCP_ENABLE_CUSTOM_AUDITS=true`; такие audit-playbook'и не должны выполнять изменения.
