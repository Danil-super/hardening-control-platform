# Загрузка OVAL и память подготовки — 14 ноября 2026 года

## Повторная проверка

Официальный каталог до и после двух полных проверок ответил штатному клиенту;
метаданные совпали с действующей политикой: 171 177 747 байт, SHA-256
`87bc54ce8fd972921c1fb51f7a7515dcfed51a5f0f74aa97c5ec17aa1feb4afc`,
генерация `2026-11-10T11:16:13.650844+00:00`.

Первый повтор действительно скачал полный XML с этим SHA-256, но дальнейшую
проверку остановил guard памяти: минимум MemAvailable 2 303 819 776 байт.
Docker сообщил OOMKilled=false; код 137 получен после целенаправленной
остановки проверочного контейнера. Это не успешная подготовка базы.
Рабочая подготовленная копия и политика не изменялись.

Причина лишнего расхода подтверждена: `prepare` сохранял список chunks,
полный raw XML и дерево Python, пока отдельный процесс OpenSCAP разбирал
тот же файл для XSD/Schematron. Новый тест до исправления обнаружил живую
ссылку на дерево при запуске native validator.

## Исправление и измерение

Код `2eccf0618010c4ab6bcbcbc160b67678148d9a2f` освобождает chunks после сборки
raw, затем raw и дерево после записи проверенного XML, перед OpenSCAP.
Размер берётся из уже вычисленного metadata.bytes. SHA-256, кодировка,
DTD/XInclude, сложность, определения, дата и оба native validator сохранены;
исходные байты XML не меняются. Новых зависимостей и параметров нет.

После исправления выполнены две отдельные загрузки из официального HTTPS
источника с настоящими XSD и Schematron: **85,9 и 82,0 секунды**, обе успешно.
Каждый процесс ограничен 2 ГиБ без swap, CPU=1; OOM/guard отсутствуют.
Минимумы MemAvailable — 4 110 880 768 и 4 390 342 656 байт.
Это конкретный feed и workload, не универсальный лимит всей панели.

Сеть и proxy-параметры повторяли рабочий контроллер. Использован обычный
`hcp-oval-audit.py prepare --validate`; TLS/certificates не ослаблялись,
сетевой ответ не подменялся и локальный файл вместо скачивания не подавался.
В проверочном контейнере установленного образа был readonly mount именно
исправленного helper. SHA-256 этого helper затем сверили с новым образом.
Для экономии диска скачанные копии после проверки хеша дедуплицированы
с уже сохранённым побайтно идентичным vendor XML; протоколы сохранены.
Подпись производителя и охват всех известных CVE этим не подтверждаются.

Все **373 Ansible/Python-теста без пропусков** прошли в контейнере 512 МиБ,
включая 38 OVAL-тестов на установленном OpenSCAP. Production build/typecheck
и **132 HTTP-проверки** прошли. Web-код не менялся.
Нативные dpkg status/SSH/libxml2/SQLite/GIO совпали с предыдущим образом;
новый полный Trivy scan не выполнялся, прежние CVE не объявлены закрытыми.
