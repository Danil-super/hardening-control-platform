# Firewall и откат из восстановленной Ubuntu — 11 ноября 2026

Из отдельной восстановленной Ubuntu выполнен полный UFW-цикл на настоящей
Astra: проверка без изменения → закрытие тестового порта → откат через сайт →
повторный OpenSCAP. Основная панель возвращена и тоже выполнила свежий аудит.
Числа и SHA: [очищенный протокол](evidence/restored-firewall-2026-11-11.json).

## Исправление реального отказа

В первой попытке firewall и откат прошли, но последующий OpenSCAP остановился:
`Timeout (12s) waiting for privilege escalation prompt`. Этот неудачный
протокол сохранён. В `327ecbe870704d442a323997ba18b8125c85392f` установлен
Ansible `timeout = 30`: медленный SSH/PAM получает ограниченное время ожидания.
Пароль, проверка ключа и правила повышения привилегий не изменялись.

Регрессия использует настоящий SSH-плагин Ansible и локальный транспорт:
задержка sudo 13 секунд воспроизводит отказ прежних 10+2 секунд и проходит
с новым значением. Явный `--timeout 1` по-прежнему завершается отказом через
3 секунды; бесконечного ожидания и автоматического повтора нет. Проверены
оба Ansible runtime образа. Прошли 618 web, 368 Python/Ansible, 235 deployment
и 125 HTTP-проверок. Первые запуски на хосте выявили отсутствие ReportLab;
полные наборы повторены успешно в окружении образа, зависимости хоста не менялись.

Установлен образ
`sha256:2bba2977f1305cf777d2c33e7f61d6609b550f7138465319de39a1a64dcaa753`.
Это дополнение к принятому образу `4bcb500`: сохранены его слои и параметры,
заменены конфигурация Ansible и файл регрессии. Полная чистая пересборка
Dockerfile и новый GitHub CI в этом этапе не выполнялись. При установке
сохранились 13 таблиц, 98 файлов отчётов, окружение и mounts.
Локальный тег образа Compose также указывает на установленный образ;
обновление тега не требовало перезапуска контейнера.

## Проверка из копии

Использована Ubuntu из [приёмки восстановления 10 ноября](ubuntu-restore-acceptance-2026-11-10.md).
В неё загружен новый образ; Config, RootFS и архитектура сверены. Docker 29
с containerd показывает OCI manifest digest вместо прежнего config digest:
сопоставление проверено через `manifest.config.digest`, а не совпадением разных ID.
После перезагрузки управляющего стенда KVM недоступен, поэтому повтор выполнен
через QEMU TCG. Обе гостевые ОС остаются на том же управляющем стенде.

Основная панель была остановлена до разрешения копии SSH-доступа к Astra.

## Оставшиеся границы

Аудит фильтрации после применения честно остаётся partial/manual: старый
nftables сообщает `xt:null`, поэтому активный UFW не доказывает полный охват
пакетных путей. Проверен внешний IPv4 TCP; для IPv6 сверена конфигурация,
но внешний IPv6-трафик, UDP и все возможные пути не испытывались.
Четыре непройденных правила OpenSCAP остаются нарушениями конфигурации.

Новый полный холодный backup с кодом `327ecbe` не принимался с нуля:
проверена прежняя копия с обновлённым контроллером. Внешние anchors/DR,
HTTPS, нагрузка 1/3/5 хостов, новый GitHub CI и подпись оператора открыты.
Приватные исходные доказательства сохранены в
`~/.local/state/hcp-evidence/ubuntu-dr-20261110-jbhsr0sm/firewall-acceptance/`.
