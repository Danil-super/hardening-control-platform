# Hardening Control Platform

Расширяемая web-demo платформа для аудита и безопасного харденинга Linux-серверов.

MVP показывает полный демонстрационный цикл: выбор профиля, запуск demo-аудита, findings, remediation planning, backup simulation, повторный аудит и отчет “до/после”. Первая версия не меняет реальную ОС и готовится к публикации на GitHub и деплою на Vercel.

## Стек

- Next.js App Router
- TypeScript
- Tailwind CSS
- lucide-react
- Mock-данные в TypeScript
- Заготовка будущего агента на Python

## Запуск

```bash
cd web
npm install
npm run dev
```

Сборка:

```bash
cd web
npm run build
```

## Основные экраны

- `/` панель со статусом демо-режима и схемой процесса.
- `/profiles` четыре профиля аудита: Basic Linux, SSH Security, Web Server, Docker Host.
- `/audit/[profileId]` запуск demo-аудита.
- `/audit/[profileId]/results` summary, score, findings, фильтры по риску и категории.
- `/remediation` выбор remediation, risk, affected files, backup, rollback и demo steps.
- `/reports` отчет “до/после” и экспорт JSON.
- `/guide` инструкция и сценарий демонстрации MVP.
- `/agent/import` автоматический или ручной импорт JSON-отчета локального агента.
- `/agent` будущий Local Linux Agent и API-контракт.

## Краткая инструкция по работе на сайте

1. Откройте главную страницу и проверьте, что платформа работает в демо-режиме.
2. Перейдите в `Профили`, выберите профиль аудита и нажмите `Запустить аудит`.
3. На странице результатов изучите оценку защищенности, риски и таблицу найденных проблем.
4. Используйте фильтры по риску и категории, затем перейдите к выбору исправлений.
5. В `Исправлениях` отметьте нужные действия и нажмите `Применить демо`.
6. Откройте `Отчеты`, чтобы увидеть сравнение “до/после” и скачать JSON-отчет.

Подробная инструкция находится в `docs/site-guide.md`.

## Связка с локальным агентом

Запустить agent bridge:

```bash
cd agent
python3 server.py
```

Затем открыть на сайте `/agent/import` и нажать `Получить аудит от агента`.

Ручной fallback:

```bash
cd agent
python3 agent.py audit --profile basic_linux --pretty > agent-report.json
```

После этого файл можно загрузить на странице `/agent/import`.

## Термины

- Audit: проверка системы на небезопасные настройки.
- Finding: найденная проблема безопасности.
- Remediation: действие для устранения найденной проблемы.
- Backup: резервная копия перед изменением.
- Откат: возврат изменения к предыдущему состоянию.
- Profile: набор правил под сценарий аудита.
- Agent: будущий локальный модуль для реальных проверок и изменений.

## Демо-режим

Демо-режим использует mock-данные и работает безопасно в браузере. Применение исправлений имитирует создание резервной копии, применение изменений, проверку и повторный аудит, создает отчет в памяти браузера и не выполняет системные команды.

## Будущий Linux Agent

Папка `agent` содержит заготовку Python Agent. В будущей версии агент должен запускаться на Ubuntu/Debian, определять ОС, запускать Lynis/OpenSCAP, выполнять YAML-правила, создавать backup, применять remediation и делать rollback.

## Деплой на Vercel

1. Опубликовать проект на GitHub.
2. Создать проект в Vercel из репозитория.
3. Указать `web` как root directory.
4. Использовать стандартные команды Next.js: install `npm install`, build `npm run build`.

## Ограничения первой версии

- Нет реального изменения Linux-хоста.
- Нет запуска `systemctl`, `ufw`, `sshd`, `nginx` на Vercel.
- Нет контейнеризации.
- Нет многопользовательской авторизации.
- Нет полной интеграции с Lynis/OpenSCAP.
